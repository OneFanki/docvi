# 平台自研壳与多宿主迁移

> 状态：**已部分退役（2026-10-24）**。本文描述的「自研壳 + 五宿主平权」载体已删除——
> 壳（`packages/shell`）、旧桌面宿主（`packages/desktop`）、单文件 viewer 都不再存在。
> 现在只有**一份渲染层、两种宿主**：桌面 app 与容器站点（见 [架构说明](../architecture/README.md)）。
> 本文仍然有效的部分是**数据设计（五）与接口设计（六）**里的内容索引协议
> （`tree.json` / `search-index.json` 的字段与产出口径），`scripts/lib/docs-core.mjs` 与
> `scripts/build-docs-index.mjs` 的注释指向这里；其余章节按历史决策阅读。
>
> 定位：设计稿 ｜ 负责人：Fanki ｜ 创建：2026-10-10 ｜ 更新：2026-10-24（标注退役范围）

## 一、功能定位

**一句话**：把渲染层从 VitePress 编译管线迁移到**零编译 + 声明式组件运行时**——内容零编译、改完即见、目录动态更新。（原文的五宿主目标已收敛为桌面 app 与容器站点两种宿主；五/六 的索引协议沿用至今。）

**用户价值**：内容更新不再等待构建（push 后毫秒级索引刷新即生效）；本地选个文件夹就能看（Tauri/工作区）；一份组件库全端一致；外部系统同步场景后续可由统一数据格式自然衍生（纯文本导出器已砍，格式预留）。

**术语**：

- **壳（shell）**：自研的 SPA——左侧目录树 + 正文渲染区 + 搜索 + 主题样式，视觉与交互对齐现有站点；
- **声明式组件**：组件 + 结构化数据（frontmatter 结构段），业务不写任何 JS；
- **ContentSource**：内容来源抽象接口（列树 / 读文档 / 取搜索索引），宿主差异全部收在此处；
- **工作区（workspace）**：一个内容目录的本地管理单元（Tauri/插件的「添加目录」）；
- **宿主（host）**：承载壳的运行环境（五类，见九）。

## 二、业务规则

- **R1 壳是唯一渲染层**：迁移完成后，站点的全部页面由壳渲染；VitePress 相关代码（`.vitepress/`、编译消费端）在对标验收通过后删除。
- **R2 内容零编译**：正文 `.md` 原文直出、客户端渲染；「动态更新」= deployer 在内容变更后刷新 `tree.json` 与 `search-index.json`（毫秒级纯文本操作，复用现有构建队列的调度，任务类型替换），不是构建。
- **R3 组件数据声明式（全量）**：21 个组件（迁移当时）一律「组件 + frontmatter 结构段数据」，业务零 JS；平台未覆盖的交互需求走 HtmlEmbed/staticDirs（iframe 沙箱）——此为唯一出口，与现状一致。
- **R4 目录协议不变**：`docs.config.yaml` 仍是唯一配置入口；无配置时壳内自动扫描 + 界面明示提示条（本地查看器场景；发布场景仍由 deployer 侧要求配置，纪律不变）。
- **R5 工作区**：本地宿主以工作区为管理单元 `{ id, 名称, 路径, 配置来源, 最近打开 }`；添加目录 = 添加工作区：有配置直接采用；无配置自动扫描并明示；**向下只探测一层**子目录的 `docs.config.yaml` 以候选列表让用户确认（支持一个父目录下多个文档仓），不隐猜。
- **R6 依赖全第三方**：markdown-it（渲染）、shiki（高亮，按需语言包）、mermaid（ESM 懒加载）、minisearch（搜索）；路由自写轻量实现（约百行：history 为主，`file:` 协议与受限宿主自动切 hash），不引 vue-router。
- **R7 组件库单源多宿主**：组件库构建为 Custom Elements ESM（`defineCustomElement`），一个版本全宿主共用；组件更新 = 各宿主以新版本资产**重新分发**（镜像/应用包/vsix），不做运行时热更新（避免宿主与组件库版本漂移）。
- **R8 移动端一步到位**：壳 v1 内建响应式——窄屏侧栏变抽屉（汉堡按钮）、触控目标 ≥ 40px、TableGraph 悬停交互补点击降级、门户/工作区卡片自适应；deployer 已监听 0.0.0.0，手机同网直访，不编译 app。
- **R9 失败与兼容**：声明的组件键缺失/未知 kind → 正文原位渲染「未知组件」占位块并控制台告警，不白屏；frontmatter 解析失败 → 按纯 markdown 渲染 + 顶部错误条；旧 `<script setup>` 写法仅在迁移过渡期由 VitePress 站点支持，壳不认。
- **R10 VS Code 插件为后续阶段**：形态 = Webview 跑完整壳（工作区 = VS Code 当前打开的文件夹，`vscode.workspace.fs` 实现 ContentSource），不做官方预览注入的单文件形态。

## 三、流程与状态机

本地宿主「添加工作区」主流程：

```mermaid
flow LR
  A[选择目录] --> B{目录有 docs.config.yaml?}
  B -- 有 --> C[采用配置加载]
  B -- 无 --> D[探测一层子目录]
  D -- 有候选 --> E[候选列表用户确认]
  D -- 无候选 --> F[自动扫描成树+明示提示条]
  E --> C
  C --> G[写入工作区列表]
```

deployer 内容更新（替代原构建流程）：

```mermaid
flow LR
  A[webhook/手动/轮询] --> B[fetch + reset --hard]
  B --> C[索引刷新: tree.json + search-index.json]
  C --> D[完成——内容已即改即见]
```

宿主加载状态机：`选内容源 → ContentSource 就绪 → 拉树 → 路由到文档 → 渲染`；任一步失败给对应空态/错误条（无工作区引导、目录不可读、文档缺失 404 页）。

## 四、权限与边界

| 角色                   | 能做什么                                              |
| ---------------------- | ----------------------------------------------------- |
| 读者                   | 五宿主内浏览、搜索、切换工作区/分支                   |
| 本地用户（Tauri/插件） | 管理本地工作区（添加/移除/重命名），完全本地无鉴权面  |
| 运维者（deployer）     | 沿用 deployer 既有权限模型（OPS_TOKEN），本功能不新增 |

**边界**：壳不做编辑（纯渲染）；不做纯文本导出/飞书转换（已砍，数据格式预留）；不做评论/协作；git 操作永远只在 deployer。与 deployer 的分工：**deployer 管内容的分发与索引，壳管渲染**。

## 八、验收标准

迁移对照以现有 VitePress 站点为基线，逐项达标后删除编译管线（R1）。

- AC1 组件声明式改造：21 个组件（迁移当时）全部支持 `components:` 数据段 + `:data` 引用，component-showcase 演示课整体迁移为新写法并逐组件对照通过（验证：人工 + 单测）
- AC2 壳渲染对照：目录树（图标/展开/落地页规则/排序）、markdown 渲染（标题/表格/代码块高亮/锚点/404）与现有站点逐项一致（验证：人工对照清单）
- AC3 搜索：关键词命中与跳转对齐现有体验；索引懒加载（首次搜索才拉）；版本不一致时提示刷新（验证：人工 + 单测）
- AC4 mermaid：块渲染与缩放交互对齐；无图页面不加载 mermaid 资源（验证：人工）
- AC5 deployer 端到端：webhook 后内容更新在浏览器**刷新即见**（无构建等待），tree/search-index 版本同步更新（验证：人工 + 脚本）
- AC6 索引任务：调度/去重/审计沿用原构建队列口径；失败不更新版本号（验证：单测）
- AC7 移动端：≤768px 侧栏抽屉化、触控目标达标、TableGraph 点击降级、门户/工作区卡片自适应（验证：人工，手机真机）
- AC8 Tauri 查看器：添加本地目录（有配置/无配置/父目录候选三场景，R5）→ 浏览/搜索全离线可用；工作区列表持久化与最近排序（验证：人工）
- AC9 五宿主矩阵冒烟：deployer 站点 / Tauri / 单文件 viewer（拖拽）/ 移动端浏览器各跑通核心浏览路径（插件为后续阶段不在本 AC）（验证：人工）
- AC10 迁移收尾：`.vitepress/` 与编译消费端删除后，`pnpm dev`（vite dev 壳 + 任意目录热更）/ `build`（壳资产构建）语义平移，全部测试绿（验证：单测 + 人工）

## 九、前端设计

**宿主矩阵**（一套组件库 + 一个壳，五宿主）：

| 宿主                     | ContentSource 实现             | 路由模式                   | 备注                  |
| ------------------------ | ------------------------------ | -------------------------- | --------------------- |
| deployer 站点            | HTTP（tree/docs/search-index） | history（服务端 fallback） | 手机浏览器同此形态    |
| Tauri 桌面查看器         | TauriFs（plugin-fs/dialog）    | hash                       | 工作区模型 + 本地存储 |
| VS Code 插件（后续阶段） | VsCodeFs（workspace.fs）       | hash（webview）            | Webview 跑完整壳      |
| 单文件 viewer            | FileReader 拖拽                | hash                       | 零服务零安装          |
| 离线内容包               | Embedded（应用内资源）         | hash                       | 形态 A 的打包变体     |

**壳界面**：视觉与交互对齐现有站点（树节点图标/选中态/字重梯度全部沿用 tokens.css）；新增——工作区启动页（卡片列表 + 添加引导 + 最近排序）、自动扫描明示提示条、移动端抽屉侧栏。

**工程布局**：`shell/`（壳 SPA + 自研路由 + ContentSource 接口与各实现）、`components/`（组件库源 + CE 构建，替代 src/components 的消费方式，源码平移）；第三方：markdown-it / shiki / mermaid / minisearch。

**Tauri 工程**：`src-tauri/`（Tauri 2 + plugin-fs + plugin-dialog；Rust 侧零自定义代码，仅清单配置）；图标/打包（NSIS）；自动更新（updater 插件）后置。
