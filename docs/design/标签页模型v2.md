# docvi 标签页模型 v2：工作区即标签，标签即工作现场

> 状态：已拍板并实现（2026-10-22）。本文是实现依据，取代旧「全局扁平文档标签」模型（`docvi.tabs.v1`）。
>
> 验收现状：P1 全部落地。运行时验收 25 项（标签模型）+ 16 项（文档模型/设置层）通过；
> 打包态再验 13 项（冒烟）+ 12 项（工作区→树→阅读→编辑→Ctrl+S 保存全链路）通过。
> 安装包产出：`apps/desktop/release/docvi-0.1.0-setup.exe`，构建命令 `pnpm docvi:dist`。

## 一、一句话定义

**一个标签页 = 一个独立的工作现场。** 文档库是唯一固定标签；从文档库打开工作区或文件都新建标签；标签内部左侧目录、右侧正文，所有导航都发生在本标签内。

## 二、为什么不是「全局文档标签」

旧模型（v1）把标签当成全局文档列表：任何入口打开文档都塞进同一条标签条。它有三个结构性缺陷：

1. **归属丢失**：侧栏始终显示「当前工作区」的树，而标签可以来自任意工作区，两者不同步。
2. **切换工作区没有界面表达**：`openWorkspace` 只换树不换正文，出现「侧栏是 B、正文是 A」。
3. **同名文档不可区分**：两个工作区都有 `index.md` 时，标签标题完全相同。

新模型把「工作区」提升为标签的作用域：标签归属是稳定事实（标签内不会跳到别的工作区），标题可读，侧栏天然同步。

## 三、标签类型

| 类型        | 身份                    | 标题                           | 侧栏                                       | 可关闭                 |
| ----------- | ----------------------- | ------------------------------ | ------------------------------------------ | ---------------------- |
| `library`   | 文档库首页              | 文档库                         | —                                          | 否（钉住、永远第一个） |
| `workspace` | 一个已登记工作区        | 文档标题（无文档时为工作区名） | 该工作区的目录树                           | 是                     |
| `file`      | 工作区外的单个 Markdown | 文档标题                       | 不显示，正文提示「该文件不在任何工作区内」 | 是                     |
| `settings`  | 设置页                  | 设置                           | —                                          | 是（单例）             |
| `plugins`   | 插件管理页              | 插件                           | —                                          | 是（单例）             |

- **应用页面也走标签**（`settings` / `plugins`），不再用独立的全局视图状态。否则会出现
  「标签条高亮着文档库、画布却是设置页」——两处都在声明自己是对的。
- 页面标签是**单例**：同一页面只存在一个，再点就是激活它。这与工作区标签「不去重」
  是两种语义，别混：工作区是工作现场，页面是全局工具。
- **没有左侧图标栏**：VS Code 那一列切的是左侧边栏里的视图，我们这没有等价的边栏视图，
  照搬会变成「切全局页面」且与文档库标签语义重复。入口改为：状态栏服务芯片 + 命令面板，
  设置/插件都能从命令面板搜到。

## 四、打开规则

| 入口                         | 行为                                                                        |
| ---------------------------- | --------------------------------------------------------------------------- |
| 文档库点工作区               | **新建** workspace 标签（两次点击 = 两个标签，不去重）                      |
| 文档库点最近打开 / 打开文件  | 工作区内的文件 → 新建 workspace 标签并直达该文档；工作区外 → 新建 file 标签 |
| 目录树单击                   | **当前标签内切换文档**                                                      |
| 目录树右键「在新标签页打开」 | 新建 workspace 标签并直达该文档                                             |
| 命令面板 · 当前工作区命中    | 当前标签内切换文档                                                          |
| 命令面板 · 其他工作区命中    | 新建该工作区的标签并直达该文档                                              |
| 正文链接跳到别的工作区文档   | 新建 workspace 标签，并提示「已在新的标签页打开」                           |
| 拖放 / 命令行 / 文件关联     | 工作区内 → 新建 workspace 标签；否则新建 file 标签                          |
| `Ctrl+T`                     | 激活文档库标签                                                              |

**标签内文档切换是「替换当前视图」而不是「新增标签」**，因此每个 workspace / file 标签必须有自己的文档历史（见第六节），否则连续点两篇文档就找不回上一篇。

## 五、标签条 UI 与设置

默认（可在设置 → 标签页修改）：

| 项         | 默认                                             |
| ---------- | ------------------------------------------------ |
| 最大标签数 | 0 = 不限                                         |
| 达到上限   | 关闭最久未使用（可选：关闭最早打开 / 拒绝新建）  |
| 排列       | 单行（可选：允许换行）                           |
| 单行溢出   | 横向滚动条（可选：等比压缩）                     |
| 宽度       | 固定 180px（可选：自适应；固定宽度可调 120–260） |

- 文档库标签在**左侧固定区，不参与滚动**；工作区标签在右侧滚动区。
- 滚动条是**覆盖式细滚动条**：开启 `OverlayScrollbar` 后不占布局（实测占位 0px），
  hover 时浮现在内容之上。**禁止写任何 `::-webkit-scrollbar` 规则**——写了会让
  Chromium 退回经典模式，滚动条重新挤占布局（标签条被压矮就是这个原因）。
- 标题**只显示文档名**，单行省略。工作区名不参与主标题（更不能用工作区 id 兜底）：
  那段 12 位哈希曾原样出现在标签上；身份信息显示在标签内的目录树顶部。
- 标签条最右端固定一个「切换标签」按钮，hover 提示 `Ctrl+Tab`。
- 自动关闭**跳过有未保存修改的标签**；候选全是脏标签时拒绝新建并提示。

### 5.1 标题栏（窗口 chrome）

标题栏只放**全局**入口，且都集中在两处：

| 位置   | 内容                                                             |
| ------ | ---------------------------------------------------------------- |
| 左侧   | 品牌标识                                                         |
| 中间   | **搜索伪输入框**（`<button>`，长得像输入框但不可输入，绝对居中） |
| 右上角 | 目录树显隐、本页目录显隐、主题切换（三枚图标按钮）               |

- **窗口内不再显示文档标题**：标题信息已经由标签承载，中间整段留给搜索框更值。
  系统层标题（任务栏 / Alt+Tab）仍同步为「文档名 · docvi」，未保存时前缀 `•`——
  否则任务栏永远只有 "docvi"，多窗口时无法分辨。
- **搜索伪输入框**：点击即打开 `Ctrl+K` 浮层，框内显示「搜索文档或命令」+ `Ctrl K` 提示。
  用 `position: absolute; left: 50%` 相对窗口水平居中，所以左侧品牌宽度变化不会让它偏移；
  宽度 `clamp(160px, 30vw, 320px)`，窗口缩到最小 880px 时右缘距按钮组仍有约 72px 余量。
  它不可输入，因此不需要处理输入法、焦点与 Esc 语义——真正的搜索只发生在浮层里。
- **面板开关放右上角**（对齐 VS Code）：目录树（`Ctrl+B`）与本页目录（`Ctrl+Alt+B`）。
  两枚按钮都带 `aria-pressed` 与点亮态，面板可见时按钮保持高亮；当前视图下没有该面板时禁用
  （文档库视图两枚都禁用，编辑态下本页目录禁用）。
- 面板开关**只在标题栏有一处**：状态栏原来的大纲按钮已删除，命令面板与快捷键是同一行为的其他入口。
- `Ctrl+B` 在编辑器内必须**放行**给 CodeMirror（加粗），全局处理器检测 `event.target.closest('.cm-editor')` 后直接 return。
- 状态栏只保留当前上下文与阅读/编辑开关（阅读/实时预览/源码、文档主题）。
- **状态栏右侧常驻 MCP 服务芯片**：运行中显示 `MCP :<端口>`（绿点），未运行显示
  `MCP 未运行`（灰点）；点击打开设置页标签并直接落到「本地服务」分区。
  服务是独立进程，用户需要一眼看到「AI 现在能不能连上我」，而不是进设置才发现它挂了。

### 5.2 文档元信息的位置

路径面包屑与「字数 · 阅读时长 · 体积」合并成**一条元信息栏，放在正文之前**：

- 读者打开长文档前就该知道要花多久；放在文末等于滚到底才看见，已经没有决策价值。
- 布局：路径在左、统计在右，同一条基线；窄屏换行时路径仍在上。
- 文末不再重复字数行；只在「复制了代码块语言」时出现一行轻提示。

## 六、标签内的文档历史

每个 workspace / file 标签维护一条历史栈：

```
history: TabDocRef[]        // { key, absolutePath, relPath, title, scrollY }
historyIndex: number
```

- 标签内打开文档 = 截断 index 之后的分支，push 新条目。
- `Alt+←` / `Alt+→` 在当前标签内前进后退，恢复对应条目的 scrollY。
- 切标签、切文档前把当前 scrollY 写回当前条目。
- 历史栈上限 50，超出丢最旧。

## 七、Ctrl+Tab 切换浮层

- 列表按**最近使用（MRU）**排序，**不含文档库标签**。
- 按住 Ctrl 连按 Tab 向后移动、Ctrl+Shift+Tab 向前；**松开 Ctrl 落地**。
- 初始选中项为「上一次使用的标签」，因此快速按一下松手即在两个标签间来回。
- 按住期间 Esc 取消；浮层也可从标签条右端按钮打开（粘住模式：点击/回车落地，Esc 或点外部取消）。
- 当前停在文档库时，初始选中 MRU 第一项。

## 七之二、搜索与查找（2026-10-22 晚定稿）

**一个搜索入口，两种查找语义分开。**

| 能力       | 入口     | 范围                         | 结果去向                      |
| ---------- | -------- | ---------------------------- | ----------------------------- |
| 全库搜索   | `Ctrl+K` | 所有工作区（当前工作区优先） | 见下方分组规则                |
| 文档内查找 | `Ctrl+F` | 当前文档正文                 | 当前文档内跳转，计数 + 上下步 |

### 全库搜索 = 命令面板

- **唯一入口**：左栏搜索页、标题栏独立搜索图标全部删除。入口多、范围不清，比功能少更伤体验。
- **不做「当前 / 全部」切换**，靠结果分组表达范围：
  - `当前工作区 · <工作区名>`：命中先列本标签所属工作区；
  - `其他工作区`：其余工作区命中，每条带工作区徽标。
- 打开行为跟着范围走：当前工作区命中在当前标签内替换；其他工作区命中新开该工作区的标签。
- 索引是**一份跨工作区索引**，主键 `workspaceId:path`（相对路径在不同工作区会重名）。
  当前工作区立即建索引，其余工作区在空闲回调里逐个补建，面板底部显示进度。
- 工作区文档变化后整体重建索引，不做增量删除——脏命中（搜得到打不开）比一次几十毫秒的重建更贵。

### 结果行排版

标题行（含徽标）→ 摘要两行 → 路径一行，三段各自占满整行宽度。路径不再放右侧固定列：
那会把摘要挤窄，右侧留一大块空白。

### 文档内查找

- 浮层固定**画布右上角**，`position: absolute` 且位于滚动容器**之外**。
  写在滚动容器里（原先在正文之后）时，sticky 的自然位置在文档末尾，表现为浮层贴右下角、
  聚焦输入框还会把整篇文档滚到底。
- 命中高亮、上/下一个、`1 / N` 计数、Esc 关闭；关闭时清掉全部高亮。
- 不使用 Chromium 的 `findInPage`：那条路要求把每篇文档换成独立 webContents，与单页多标签的模型冲突。

## 八、文档模型（单一真相源）

同一文件可能被多个标签引用（分屏之前虽然只有一个可见，但切换标签时不能丢未保存内容）。

- 以**归一化绝对路径**为 key 维护文档记录：`text`（缓冲区）、`diskText`、`mtime`、`size`、`dirty`、`conflict`。
- 标签只持有文档引用，不持有正文。
- 阅读态渲染缓冲区（不是磁盘内容），有未保存修改时状态栏显示。
- 保存、冲突判定、草稿都按路径收口在文档模型里；草稿仍是 `userData/drafts/<path-hash>`。
- 外部改动：无未保存修改 → 静默重载；有修改 → 冲突状态，由当前显示的视图弹处理框。

## 九、持久化

| 文件                     | 内容                                  | 维护方                         |
| ------------------------ | ------------------------------------- | ------------------------------ |
| `userData/settings.json` | 主题三维、语言、标签页设置            | 用户 / AI 可改，可导出         |
| `userData/session.json`  | 标签列表、激活项、MRU、历史、展开状态 | 程序自动（防抖 600ms）         |
| `userData/service.json`  | 端口、局域网、访问令牌                | 程序自动（令牌敏感，独立文件） |

- 首次启动读旧 localStorage（`docvi.*.theme`、`docvi.locale`、`docvi.tabs.v1`）写进新文件，标 `schemaVersion`，然后删除旧键。
- `settings.json` 外部修改自动生效（监听父目录 + 文件名过滤）；解析失败保留上一份并在设置页报错。
- 首帧不闪：preload 用一次同步 IPC 取启动快照，暴露 `window.docvi.bootSettings`。

## 十、右键菜单

**标签上**：关闭、关闭其他、关闭右侧、复制标签页（workspace / file）、复制路径、重新加载、标签页设置。

**目录树节点上**：在新标签页打开、复制相对路径。

**工作区（文档库列表）上**：在新标签页打开、移除工作区。

所有菜单项同时注册为命令（命令面板可搜），保证「快捷入口必有菜单入口」。

## 十一、明确不做（本轮）

- 分屏 / 拖拽合并标签（P2，依赖标签模型稳定后另做）。
- 插件面板的类别 tab 与包详情（等标签模型稳定后单独一轮）。
- 同一文件双栏同时编辑（P2 分屏时基于文档模型自然支持）。
