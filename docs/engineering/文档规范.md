# 文档规范

> 目标：任何时候打开一篇文档，都能在 30 秒内知道它是否还可信、该信哪一篇。

## 一、文档分区（按职责，不按主题）

| 目录                       | 写什么                                                       | 不写什么           |
| -------------------------- | ------------------------------------------------------------ | ------------------ |
| `docs/project/`            | 项目总览、名词表、上手路径                                   | 实现细节、决策推导 |
| `docs/engineering/`        | 工程规范：目录、文档、契约测试、踩坑                         | 某个功能的业务规则 |
| `docs/architecture/`       | 结构真相源：组件协议、模块边界                               | 未来计划、设计方案 |
| `docs/design/`             | 设计推导：为什么这样设计、被否方案、协议演进                 | 已过时的现状快照   |
| `docs/features/<feature>/` | 单个复杂功能的四件套（ARCHITECTURE / SPEC / ROADMAP / IMPL） | 跨功能的通用规范   |
| `docs/archive/`            | 历史归档（只读，不参与链接校验）                             | 仍在使用的内容     |

## 二、单一事实源

- 同一个事实只允许一处详细定义，其他位置只链接。
- **代码是行为真相，文档是意图真相**：行为与文档冲突时，先判定哪边错了，再一起改，不允许只改一边。
- 版本变更摘要不复制设计细节，只给结论 + 链接。

## 三、改一次压缩一次（硬约束）

- 改文档时**顺手删除**已过时内容，而不是在后面追加「补充：……」。
- 同一结论出现多份 → 合并为一份详细版本，其余改为链接。
- 不设字数上限；判据是「这篇是否还值得读」，不是数字。
- 历史决策需要保留时进 `docs/archive/`，并在原位置留一行指向归档。

## 四、命名与语言

- 人读文档用中文命名（`标签页模型v2.md`）；固定语义文件用英文固定名（`AGENTS.md`、`SKILLS-INDEX.md`、`AGENTS.md` 引用的模板名、ADR）。
- 技术专名、API 字段、命令、路径保持原文，不翻译。
- 标题层级从 `#` 开始，一篇只一个 H1。

## 五、临时产物

- 一次性讲解页、截图、探针脚本、迁移草稿 → `.temp/`（已 gitignore），禁止进 `docs/`。
- 需要长期留存的探针结果 → 写进对应 feature 的 `IMPL.md` 或踩坑库，附日期与复现命令。

## 六、链接

- 跨文档用**相对路径**，确保换机器、换克隆位置都可用。
- `pnpm docs:check` 校验 `docs/` 下全部 md 的相对链接、`AGENTS.md` 与 `SKILLS-INDEX.md` 的反引号路径引用。
- 归档区（`docs/archive/`）不参与校验（历史只读，链接可能已失效）。

## 七、AGENTS.md 体量

- 15KB 软上限（警告）、20KB 硬上限（失败）。
- 新增硬约束前先下沉：详细规范移到 `docs/engineering/`，AGENTS.md 只留结论与指针。

## 变更触发

- 新增文档分区 / 改校验规则 → 同步本文件、`scripts/check-docs.mjs`、`AGENTS.md` 的「按任务读取」表。
