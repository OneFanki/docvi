# 契约测试规范

> 测试的职责是**锁定不变量**，不是记录「代码长什么样」。一条测试只有在「实现改变但契约不变时仍然通过」才是好测试。

## 三纪律

1. **断言行为，不断言实现**：输入 → 输出、错误码、边界、事件顺序。禁止断言源码字符串、函数调用次数、内部变量名。
2. **写哨兵，不写快照**：对协议兼容性用「旧客户端请求仍成功」这类哨兵；不要用整段快照（会把无关改动变成红）。
3. **不做变更检测器**：`expect(source).toContain('...')` 式的测试一律禁止——它只会在重构时误报，不会在行为错时报警。

## 新增契约测试时

- 先问：**这条测试在什么行为变化时应该红？** 答不出来就不要写。
- 测试名写清「场景 + 期望」，不写「应该工作」。
- 失败信息要能直接定位：带上实际值、期望值、输入路径。
- 涉及文件系统 / 端口 / 进程的测试，必须用唯一临时目录与唯一端口，并在 `finally` 清理。

## 门禁接入

- `pnpm verify` 必须包含新增的契约测试；只写测试不接门禁等于没写。
- 门禁脚本本身的关键分支（如路径判定、协议版本白名单）要有单测。

## 变更触发

- 新增跨包协议 / 新宿主 / 新安全边界 → 在本表补一行，并落地对应测试。
