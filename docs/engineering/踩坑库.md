## 构建与打包

### os error 32：运行中的 app 锁住构建产物（2026-10-16）

- **现象**：Tauri 出包反复报 `另一个程序正在使用此文件`，指向 `target/release/WebView2Loader.dll` 或主程序 exe。杀进程、清 Docker、删 target 都无效。
- **根因**：运行中的实例以 **image 映射**持有这些 DLL/exe；tauri-build 每次构建都会 `fs::copy` 覆盖。
- **规避**：退出实例后重跑；或先改名被占文件（`mv X.dll X.stale.dll`，运行中进程映射不受改名影响），出包后删 `.stale`。
- **验证**：PowerShell `[IO.File]::Open($f,'Open','ReadWrite','None')` 可精确判断是否被独占。

### pnpm 不提升依赖导致 CJS 包白屏（2026-10）

- **现象**：内容根或宿主解析链取不到 `dayjs` 等 CJS 包，报 `does not provide an export named 'default'`。
- **根因**：pnpm 默认不提升传递依赖，CJS 包被原样 `@fs` 伺服。
- **规避**：`pnpm-workspace.yaml` 设 `shamefullyHoist: true`（已设）；新增构建链时确认该配置仍在。

## 进程与测试

### 孤儿无头浏览器拖垮机器（2026-10-16 启动，2026-10-19 发现）

- **现象**：周一电脑发烫、鼠标卡死；任务管理器里 40+ 个 Edge/WebView2 进程，GPU 进程 CPU 累计数千秒。
- **根因**：后台 `&` 启动的无头浏览器脚本退出后，Windows 无「父死子亡」机制，进程成孤儿持续运行 5 天。
- **规避（硬纪律）**：无头测试必须**唯一端口 + 唯一临时 profile**；同一命令块末尾**无条件** `taskkill` + 删目录；会话结束前全局巡检。
- **教训**：不要只依赖脚本自身清理——脚本可能被中断。

### 误杀用户的服务进程（2026-10）

- **现象**：为解锁构建文件杀掉 `docs-studio-serve.exe`（Tauri 时代的独立进程名；Electron 时代改为 `utilityProcess` 拉起的子进程，判据相同），结果断了用户正在用的 MCP / 分享。
- **根因**：按进程名判断归属，而该进程是 app 的 `ensure_service` 拉起的用户实例。
- **规避**：**判断归属看命令行参数**——`--data-dir` 指向 app 数据目录 = 用户的；指向临时目录 = 测试的。禁止 `taskkill /IM`。

### shell 工作目录跨调用漂移（2026-10）

- **现象**：上一条命令 `cd` 到子目录后，下一条命令的相对路径全部错位。
- **规避**：关键操作用绝对路径，或每条命令显式 `cd`；批量命令写在同一命令块内。

### 单测把用户真实数据目录搬走（2026-10-19，严重）

- **现象**：桌面端「旧数据迁移」单测跑完后，`%APPDATA%/com.fanki.docs-studio-viewer/shares.json`
  消失（含用户设置的端口 8610 与「局域网开」）。该数据目录与迁移逻辑都属 Tauri 时代，现已随重构删除，
  但下面这条纪律对任何「读写真实用户路径」的函数依然成立。
- **根因**：`migrateLegacyData(targetDir)` 内部直接取 `legacyDataDir()`（真实用户目录），
  测试只传了 target，源目录默认值就指向了用户数据；测试结束 `rmSync` 临时目录把数据一并删掉。
- **规避（硬纪律）**：
  1. 任何「读写真实用户路径」的函数的**源路径必须可注入**，默认值只用于生产调用；
  2. 单测一律显式传临时目录，且测试里禁止调用无参默认值；
  3. 迁移函数必须自带「源与目标相同/互为父子 → 拒绝移动」的防御。
- **恢复**：按 `serve.log` 的启动行（端口 / 局域网 / 分享条数）重建配置，事后核对目录内容。

## Git Bash / 终端

### grep 含斜杠模式静默零命中（2026-10）

- **现象**：`grep "_/preview" file` 返回 0 行，连 `-F` 都失败，误判「代码里没有」。
- **根因**：MSYS 把含 `/` 的参数当路径转换。
- **规避**：模式写 `\/` 转义，或改用不含斜杠的关键词；不要给目录参数乱加 `MSYS_NO_PATHCONV=1`（会让 ugrep 报 invalid option）。

### 中文显示为乱码是控制台假象（2026-10）

- **现象**：Git Bash 里 curl 输出、日志中文全乱码，怀疑编码 bug。
- **根因**：控制台按 GBK 渲染 UTF-8 字节。
- **规避**：用 `node -e` 或写入文件后以 UTF-8 读取验证；不要据此改代码编码。

### bash + JSON 双层转义把路径写坏（2026-10）

- **现象**：写 `shares.json` 后程序读不到，路径变成单反斜杠导致 JSON 非法，静默走默认值。
- **规避**：用 `node -e` 构造并写入 JSON，或 heredoc + 单引号；不要用多层 shell 引号拼 JSON。

## 前端与 i18n

### i18n 审计脚本误报（2026-10）

- **现象**：审计报 2 处缺失 + 7 处冗余，实际都存在。
- **根因**：脚本未抓 `data-i18n-aria` / `-ph` / `-title`，未还原 `\n` 转义，还把基础设施注释里的示例当词条。
- **规避**：审计脚本要覆盖全部 `data-i18n-*` 变体、先反转义再比对、排除注释；修完跑全量归零再信结果。

### 相对 base 差异导致资源 404（2026-10）

- **现象**：app/viewer 打包后白屏或图标丢失。
- **根因**：站点 `base: '/'`、app/viewer `base: './'`，硬编码绝对路径在 `file://` 下失效。
- **规避**：一切资源引用走相对路径或由构建注入的基址；新增宿主时核对 `vite.config.ts` 的 base。

## 迁移期（Tauri → Electron）新增条目

### Electron utilityProcess 生命周期（2026-10-19）

- **事实**：`utilityProcess.fork()` 的进程**跟随主进程退出**，与「平台退出服务继续」冲突。
- **规避**：该能力用同一可执行文件的 `--service` 无窗口模式实现，不依赖 utilityProcess 存活。

### sandbox 模式下 preload 必须是 CommonJS（2026-10-19）

- **现象**：`window.docsStudioHost` 为 undefined，壳判定成站点宿主，本地内容源报「内容源不可用：Failed to fetch」。
- **根因**：`sandbox: true` 时 Electron 只加载 **CJS** preload；`.mjs` 被**静默跳过**，不报错。
- **规避**：preload 用 `.cjs` + `require('electron')`；主进程引用同步改名。

### 打包后服务层不在安装包里（2026-10-19）

- **现象**：安装版窗口能开、界面正常，但本地服务起不来——插件目录空、MCP / 分享全不可用。
- **根因**：electron-builder 只打包 `packages/desktop` 自己的文件；服务层在
  `packages/server`，既没进 asar 也没进 extraResources，且安装目录下 module 解析
  也找不到 `yaml`。
- **规避**：`scripts/bundle-server.mjs` 用 esbuild 打成单文件（依赖全内联），
  经 extraResources 落到 `resources/serve/serve.cjs`；主进程安装版指向它。

### esbuild 打 ESM 单文件时 CJS 依赖的 require 失败（2026-10-19）

- **现象**：`Dynamic require of "process" is not supported`——yaml 的 CJS 构建里
  有 `require('process')`。
- **规避**：产物格式改 `cjs`；同时源码里 `import.meta.url` 在 CJS 下不存在，
  路径推导要写成 `typeof __dirname === 'string' ? __dirname : fileURLToPath(import.meta.url)`。

### electron-builder 的 --config 与 --project 路径叠加（2026-10-19）

- **现象**：`--config packages/desktop/electron-builder.yml --project packages/desktop`
  被解析成 `packages/desktop/packages/desktop/electron-builder.yml`。
- **规避**：`--project <包目录> --config <包内相对路径文件名>`（config 相对 project 解析）。

### Electron 主进程里动态 import 绝对路径（2026-10-19）

- **现象**：`await import('C:\path\to.mjs')` 抛 `ERR_UNSUPPORTED_ESM_URL_SCHEME`。
- **根因**：ESM loader 只接受 `file:` / `data:` / `node:` / `electron:` 协议。
- **规避**：`import(pathToFileURL(abs).href)`；生产代码优先静态 import（打包器会处理）。

### 等宽字体栈里的中文会变成宋体（2026-10-19）

- **现象**：时间轴的「领取」、决策卡的「触发：本地成功状态已落盘」、风险标签、
  接口鉴权徽标——这些放在等宽字体里的中文全是衬线体，和周围的无衬线正文打架。
- **根因**：`--at-font-mono` 是 `JetBrains Mono, Consolas, 'Courier New', monospace`，
  这几个**都没有中文字形**。浏览器找不到中文字形时会落到系统默认等宽字体——
  Windows 上是宋体（衬线）。
- **规避**：等宽栈中间插入中文无衬线回退
  （`… Consolas, 'Microsoft YaHei', 'PingFang SC', monospace`），拉丁走等宽、
  中文走黑体。另外把「内容是中文而不是代码」的类（时间轴时间、决策卡证据、
  风险标签、接口鉴权徽标）直接改回 `--at-font-sans`。
- **纪律**：等宽字体只用于真正的标识符（字段名 / 路径 / 类型 / 方法名）；
  中英混排的说明性文字一律 sans。

### 画布组件的缩放必须防「布局中间态」（2026-10-19）

- **现象**：给流程图 / 状态机 / 表关系图加「自动适应视口」后，初始缩放停在
  30%（最小档）或 50%，而手动点一次「适应」立刻变成正确的 72%。
- **根因**：挂载当帧内层 SVG 的 `width/height` 还没应用，`offsetWidth/offsetHeight`
  读到的是中间态（实测内容宽 30、视口宽 0）；更糟的是内嵌宿主（IAB 面板）
  的 **ResizeObserver 完全不回调**，之后没有任何时机纠正。
- **规避**：`fit()` 里对内容与视口尺寸都设下限（< 40 / < 80 直接跳过，
  不据此写缩放值）；延时重算用 `setTimeout` 而不是 `requestAnimationFrame`
  （rAF 在不可见的内嵌面板里可能完全不推进）；同时监听 `window.resize` 兜底。
- **纪律**：任何「按容器尺寸算比例」的代码，先判尺寸有效性再计算；
  不要假设 ResizeObserver 一定回调。

### 插件资产被 immutable 缓存挡住同版本更新（2026-10-19）

- **现象**：改完插件组件样式并重建，刷新页面完全没变化；用 `getComputedStyle`
  读到的仍是旧规则，只有换一个 origin（换端口）打开才生效。curl 直接取
  `/plugins/docs-plugin-base/0.1.0/dist/style.css` 返回的**是新内容**。
- **根因**：资产 URL 只有 `/plugins/<name>/<version>/…`，服务端按「版本段在
  URL 里 → 包内容不可变」回 `Cache-Control: public, max-age=31536000, immutable`。
  但开发期（以及热修）经常**同版本改内容**，URL 没变，浏览器按 immutable
  直接不请求——服务端内容再新也没用。
- **规避**：服务端在插件目录条目里给出 `build` 指纹（入口与样式文件的
  「大小 + 修改时间」摘要），壳把它拼成 `?v=<指纹>`。路径段不变，
  「版本与登记不符即 404」的校验不受影响；旧服务没有 `build` 字段时退回原行为。
  两处服务端（`packages/server` 与 `deployer`）必须同口径。
- **纪律**：凡是给资源发一年 `immutable` 的，URL 必须真正随内容变化
  （内容哈希或指纹参数）；只靠版本号在「同版本改内容」时会静默失效。

### 旧版服务被「复用」导致功能静默缺失（2026-10-19，已升级）

- **现象**：Electron 版界面一切正常，插件面板能列出组件，点「预览」却显示
  「示例加载失败 / 端点不可用（HTTP 404）」——只有预览坏，其余都对。
- **根因**：旧 Tauri 版的 Rust 服务仍在 8610 监听并应答 `/health`
  （`{"ok":true,"version":"0.1.0",...}`，无能力指纹）。新宿主的 `healthy()`
  只判 `ok === true`，于是把**另一套实现**当成自己的服务复用；旧服务没有
  `/api/plugins/:name/example` 端点，预览自然 404。同理分享存储格式也不同
  （旧版 YAML / 新版 JSON）。
- **规避**：`/health` 增加能力指纹（`service` + `api` 版本）；宿主侧
  `probeService()` 把端口状态分四类 `none | ours | legacy | foreign`，
  `healthy()` 只认 `ours`；启动时遇到 `legacy`/`foreign` **自动后移找空闲端口**
  并写回配置，面板提示「原端口已被占用」。探活口径也一并收紧：
  **只有 `ECONNREFUSED` 才算空闲**，超时/非 200/非 JSON 一律按已占用处理
  （否则会 spawn 到已占端口上撞 `EADDRINUSE`）。
- **纪律**：任何「探测端口上是不是我的服务」的代码，都必须校验**能力指纹**，
  不能只看状态码或 `ok` 字段——同端口可能住着上一个版本的同名服务。

### hash 路由下改 location.hash 会触发两次渲染（2026-10-19）

- **现象**：组件预览页整块内容**叠出两遍**（两条返回栏 + 两篇示例）。
- **根因**：改 `location.hash` 时浏览器同时派发 `popstate` 与 `hashchange`，
  路由两个监听都 `emit`，文档加载跑了两趟；异步渲染先清屏后 append，
  第二趟清屏后第一趟的结果才落地。
- **规避**：路由 `emit` 按「路径 + 锚点」去重；异步渲染路径（`showPluginPreview`）
  额外持有渲染代际号，等待返回时若代际已变则丢弃结果。

### 分享页白屏：相对资产地址被分享前缀带偏（2026-10-19，已升级）

- **现象**：打开分享链接（`/s/<id>/`）整页白屏，只剩顶栏文字与骨架；控制台报
  `Failed to load module script: Expected a JavaScript-or-Wasm module script but the
server responded with a MIME type of "text/html"`。
- **根因**：桌面安装包内嵌的是 **app 变体**壳（`base: './'`，为 `file://` 而设），
  `index.html` 里写的是 `./assets/index-xxx.js`。分享页挂在 `/s/<id>/` 下时，
  浏览器把相对地址解析成 `/s/<id>/assets/index-xxx.js`——服务端在分享目录里
  找不到该文件，**回落到壳 HTML**，于是模块脚本拿到 `text/html` 被拒。
  容器版用的是站点变体（绝对路径 `/assets/…`），所以只有桌面分享踩到。
- **规避**：服务层在**分享路由**回落的壳 HTML 里注入 `<base href="/">`，
  把相对基准钉回站点根；站点入口不加（本就绝对路径，注入反而多一次替换）。
  注意 `<base>` 只对其后的元素生效——注入点必须是 `<head>` 内最前（无 head 的
  极简文档则紧跟 doctype）。
- **纪律**：任何「同一份 HTML 在多种路径深度下复用」的场景，先确认其资产
  引用是绝对还是相对；相对时必须显式给基准（`<base>` 或构建期重写）。

### 平台 `/_` 前缀会拦掉壳的前端保留路由（2026-10-19）

- **现象**：直接访问/刷新 `/__local/<doc>` 得到纯文本 `not found`（白屏无报错）。
- **根因**：deployer 把 `/_` 当平台自渲染页命名空间，未知路径一律 404；
  `/__local/` 也以 `/_` 开头，被同一条兜底拦下。此前 `/_/preview/` 也踩过同样
  的坑，加了白名单后新路由又忘了同步。
- **规避**：保留路由白名单集中在一处判断（当前在 `deployer/src/httpd.mjs` 的
  `/_` 兜底前），新增壳前端保留路由时必须同时加；`deployer/test/routes.test.mjs`
  锁住「放行的能拿到壳入口、未放行的仍 404」。

### markdown-it 把自定义元素包进 `<p>`，直接子选择器全部落空（2026-10-19）

- **现象**：给组件写 `.at-doc > .at-tabletabs { max-width: … }` 后毫无效果，
  实测组件宽度仍是 688；用 `getBoundingClientRect` 打印祖先链才发现 DOM 是
  `.at-doc > p > at-table-tabs > figure.at-tabletabs`。
- **根因**：Markdown 里的 `<at-table-tabs …></at-table-tabs>` 是**段内 HTML**，
  markdown-it 按 CommonMark 规则把它当作段落里的内联标签，包一层 `<p>`；
  自定义元素本身又渲染成 `<figure>` 外壳。所以「组件根类」并不是 `.at-doc`
  的直接子元素，`.at-doc > .xxx` 一定命不中。
- **规避**：用 `:has()` 提升**包裹层**：`.at-doc > p:has(> at-table-tabs)`。
  更稳的做法是放宽 `.at-doc` 容器、让文字类块各自锁阅读列（当前实现），
  这样新增组件不必逐条登记包裹层选择器。
- **纪律**：任何「给正文里的插件组件调布局」的 CSS，先用 `getBoundingClientRect`
  - `parentElement` 链确认真实层级，不要照着模板以为的结构写选择器。

### 正文绝对行高会被组件继承，每个字段行撑高三倍（2026-10-19）

- **现象**：表关系卡单个字段行高 57px、接口清单每行 92px，组件内部 12px 的
  小字也被撑到 28px 行高，整页极长且疏松。
- **根因**：`.at-doc { line-height: 28px }` 是**绝对值**。子元素没有自己声明
  line-height 时继承的是**计算后的 28px**，而不是「按自身字号换算」。
- **规避**：正文容器改用无单位比例 `line-height: 1.75`（16px × 1.75 = 28px，
  与旧设定逐像素一致）；子元素按自身字号重算行高。组件内部再对小字单独
  声明 `line-height: 1.4~1.5` 作为双保险。
- **纪律**：可继承的排版属性（line-height / letter-spacing）在容器上优先用
  无单位值，尤其当容器里混排多种字号时。

### `will-change: transform` 会把矢量内容变成位图放大（2026-10-19）

- **现象**：画布类组件用 `transform: scale()` 放大到 200% 时整图发虚，节点文字
  与连线都糊成一片；缩放回 100% 又恢复锐利。
- **根因**：`.at-flow__content { will-change: transform }` 把内容提升为**合成层**。
  合成层在当前分辨率下**只栅格化一次**，之后的缩放是对这张位图做贴图放大，
  SVG 的矢量性质完全失效。这个属性本意是「提示浏览器提前分层以提升动画帧率」，
  在**静态交互缩放**场景里反而是负优化。
- **规避**：删除 `will-change`，让每次 scale 变化都按新倍率重新光栅化（现代浏览器
  对 transform 动画本身已有优化，不需要手工提示）。实测同样的 200% 倍率下
  `getComputedStyle(el).willChange === 'auto'`，文字边缘恢复矢量锐度。
- **纪律**：`will-change` 只加在**真正持续动画**的元素上，且用完要移除；
  任何「静态内容 + 用户驱动连续缩放」的容器都不该加。

### 拖拽画布会顺手选中整页文字（2026-10-19）

- **现象**：在流程图/状态机上按住拖动，松手后满屏内容变成蓝底选中态，
  再点一下才恢复——演示时非常难看。
- **根因**：`pointerdown` + `pointermove` 的拖拽手势与浏览器的**文本选择**手势
  共用同一套指针事件；只 `preventDefault()` 在 `pointermove` 上不够（选择已在
  `pointerdown` 时开始）。SVG `<text>` 与普通 HTML 文字都可被选中。
- **规避**：拖拽开始时给 `document.body` 加 `.at-drag-lock`（
  `user-select: none !important` 覆盖所有后代，含 `-webkit-` 前缀），
  `pointerup`/`pointercancel` 时移除。用 body 类而不是给组件加内联样式，
  是因为指针可能在拖拽途中移出画布、落在正文上，选中范围会一直扩展到那里。
- **纪律**：凡是自定义拖拽手势，都必须同时「锁选中 + 锁触摸滚动」
  （`touch-action: none`），两者缺一都会在触屏/触控板上漏事件。

### SVG 回边连线贴着节点画，标注被节点框压住（2026-10-19）

- **现象**：状态机里「等待上传 → 上传中」这条向上的回边，弧线横穿中间层节点、
  条件标注「重新领取」被节点框盖住一半；把弧改到右侧仍被同行节点挡住。
- **根因**：三层问题叠加——① 回边的**端点**落在源底/目标顶，水平段必然跨过
  中间行；② 源节点在行内不是最右节点时，从右缘出弧会立刻撞上同行右侧的节点；
  ③ 画布宽度只按节点行宽计算，回边通道与标注直接落到 `viewBox` 外被裁掉。
- **规避**：① 走「专用通道 + 折线」：从源节点**顶边**进入源行上方的行间空隙，
  沿所有节点右侧的竖向通道上升，再从目标行上方空隙横向折回、从目标顶边进入——
  两段水平线都落在无节点的空白带里；② 画布宽度按「行宽 + 通道预留」计算，
  通道数（多条回边并排）每条错开 24px；③ 回边目标在第一行时顶部额外留
  `TURN_OFFSET`，否则横向段被 `viewBox` 上缘裁掉。
- **纪律**：手写图布局时，「线不压节点」要按**采样验证**（`getPointAtLength`
  逐点判断是否落进节点框），不能只看截图或几何直觉；SVG 截图在滚动容器里
  还会拼帧，肉眼判断更不可靠。

### 行间带里的多条连线标注会挤成一句（2026-10-19）

- **现象**：状态机中「文件未传完：受控重试」与「文件已全传：成功补报」两条
  并行分支的标注在同一行间带里并排，文字几乎连成一句，读不出是两条边。
- **根因**：所有正向边标注都居中在 `(sy + ty) / 2`，同一带内多条边必然同 y；
  行距只按「一条药丸够不够」设计，没考虑同带多标注。
- **规避**：先统计每条行间带的标注条数，按条数把行距加高
  （`max(ROW_GAP_BASE, lanes × LABEL_LANE_H + 12)`），绘制时按带内序号把
  标注分配到各车道（`sy + (ty - sy) / lanes × (index + 0.5)`）。
- **纪律**：凡是「自动布局 + 自动标注」的图，标注也要参与布局测量；
  只给线段留空间、不给标注留空间，长标注一定会互相压。

### HTML 包裹层上的 CSS transform 不作用于其中的 SVG 文字（2026-10-19）

- **现象**：状态机缩放 200% 以上时，节点边框放大到 3 倍、文字仍按 100% 尺寸绘制在
  左上角，看起来像「框大了一圈、字缩在角落里」；几何数据（getBoundingClientRect）
  却显示文字宽度正好是 3 倍——**测量与绘制不一致**，很容易误判成布局算错。
- **根因**：Chromium 对「HTML 元素带 CSS transform + 后代为 SVG」的组合存在绘制缺陷：
  作为合成层栅格化时，SVG 内的 `<text>` 字形不随外层 transform 缩放，而 `<rect>`
  等图形会。同一个 SVG 里的两类元素因此落到不同倍率上。
- **规避**：把 transform 挂到 **`<svg>` 元素自身**（`svg.style.transform = …`），
  让文字与图形在同一坐标系里一起缩放；外层包裹 div 只负责提供自然尺寸（测量用
  `content.offsetWidth`，仍读包裹层）。
- **纪律**：任何「HTML 容器 + 内嵌 SVG + CSS 变换」的组合，变换必须落在 SVG 自己身上；
  验证方法是放大到 2～3 倍后核对**文字**与**边框**的屏上尺寸是否同比。

### 缩放后的 getBoundingClientRect 是屏幕坐标，不能直接当 SVG 坐标用（2026-10-19）

- **现象**：表关系图缩放 43% 时，所有连线的箭头指向空中、完全不贴表卡边缘。
- **根因**：测量函数拿 getBoundingClientRect 的差值当 SVG 的用户坐标画线。
  该 API 返回的是**已经过 transform 缩放**的屏幕坐标，43% 缩放下每条线的落点
  都被压缩到 43% 的位置。
- **规避**：统一除以当前 scale 换算回布局坐标（`toLocal = v => v / scale`）；
  SVG 尺寸取 offsetWidth / offsetHeight（不受 transform 影响）。
- **纪律**：一条规则——**测量用 offsetWidth / scrollHeight 或除以 scale，
  绘制用布局坐标**；两者混用必然错位，而且只在非 100% 缩放下才暴露。

### 手写分层布局的三个必备能力（2026-10-19）

- **现象**：节点从 6 个涨到 16 个后，同类图「一眼看过去很乱」：连线大面积交叉、
  跨行边从中间节点框里穿过去、多条边的条件标注叠成一团。
- **根因**：初版分层只做了「最长路径分层」+ 按声明顺序排列。缺少三件事：
  ① 回边识别（用 BFS 分层会把回边两端压到同一行，画成退化的锯齿）；
  ② 跨行降交叉（同层节点按声明顺序排，边会成片交叉）；
  ③ 标注参与布局（标签位置只按边中点算，从不检查节点框与其它标签）。
- **规避**：抽成共享引擎 `graph/layered.ts` + `graph/labels.ts`：
  - DFS 找回流边 → 只对剩余 DAG 做最长路径分层；
  - 重心排序（barycenter）上下各扫数趟，按邻居平均列号重排同层节点；
  - 标注先夹进行间带（带内无节点），再做节点 / 已放标注的二维避让；
  - 跨 ≥2 行的边与回边一律走外圈折线通道，两段水平线都落在行间空隙里。
- **纪律**：手写图布局要按**采样验证**（getPointAtLength 逐点判断是否落进节点框），
  并造一份 ≥16 节点的压测文档常态化回归——6 节点的示例永远测不出这些缺陷。

### 段首加粗是标题不是强调：长段落失去扫读锚点（2026-10-19）

- **现象**：PRD 里「HTTP 失败与有限重试。批量切换请求超时…」这类段落，一整段
  300~420 字、每行 34 字、十几行连成一片，读者找不到入口只能逐字读。
- **根因**：全库有 **643 处**统一写法——`**术语**：定义`、`**短语**。正文`、
  `**小节名**` 独立成段、列表里的 `1. **步骤名**` + 缩进说明。它们在语义上都是
  「标题 + 说明」，但 Markdown 只有 `<p><strong>` 一种表达，渲染出来是没有层次的
  连续正文。**问题不在文档写作，在渲染层把结构压平了。**
- **规避**：在 markdown-it 的 core 规则里识别四种形态，打类名交给 CSS 做视觉分层：
  - `at-term`：段首 strong 紧跟 `。`/`：` → 左侧 3px 竖线 + 术语换行 + 行距 1.85；
  - `at-step`：列表项内 strong 独占首段**且该项后面还有正文** → 步骤标题加重；
  - `at-question`：术语以 `？` 收尾 → 块级标题但不加竖线（设问≠术语）；
  - 其余不动。
- **判据收紧（防止误伤）**：
  - 列表项必须「后面还有别的段落」才升格——`- **注意**：xxx` 这种单段列表项
    是常见强调写法，110 个列表段落全升格会把结构打乱；
  - 加粗内部以 `。`/`！` 收尾的整句加粗不升格（实测 2 处整句论断）；
  - 长度上限 48 字（带括注的标题正常放行）；
  - 文档级 `terms: false` 可关。
- **⚠️ markdown-it token 坑**：段落 inline 的 `children[0]` 是**内容为空的 text token**
  （strong_open 在 `children[1]`），段尾同理有一个空 text。按 `children[0].type`
  判断会永远落空——这条规则曾因此静默失效一整轮（渲染出 0 个术语块）。
- **验证**：156 篇真实文档全库回归，700 处术语块 + 15 处步骤标题 + 30 处设问，
  0 处误判；11 项单测锁住四种形态与四个反例。

### 深色模式加粗看不出来：光渗效应下只能靠亮度差补字重差（2026-10-19）

- **现象**：浅色模式下加粗很清楚，切到深色模式整页「白花花一片」，`font-weight: 700`
  与 `400` 几乎分不出来；用户原话「对加粗不敏感」。
- **根因**：深底浅字存在**光渗（irradiation）效应**——亮色字形在暗背景上边缘发亮、
  笔画视觉膨胀，400 与 700 的粗细差被吃掉大半。此时正文与加粗如果**同一个亮度**
  （旧版都是 `--at-text: #e6e8ee`），就只剩 300 的字重差在撑，肉眼几乎无感。
- **规避**：新增 `--at-text-body` token，深色下取 `#c5cbd8`（比 `--at-text` 暗一档），
  正文用它、加粗与标题保持 `--at-text`。亮度差（实测 relative luminance 0.595 vs 0.807）
  把字重差补回来。`#c5cbd8` 对 `#1b1e27` 对比度约 9.6:1，仍远超 WCAG AAA（7:1）。
- **⚠️ 连带坑：标题不能跟着调暗**。第一版把 h5/h6 改成 `--at-text-2` / `--at-text-muted`
  想「弱化低层级标题」，结果**标题比正文还暗**——层级倒挂（正文 0.595、text-2 更暗）。
  正确做法：所有标题与加粗统一用 `--at-text`（比正文亮），层级只靠字号/字距/间距区分。
- **纪律**：改正文基准色前，先把「正文 / 加粗 / 各级标题」的亮度列成一张表核对，
  保证**正文 < 加粗 = 标题** 的单调关系；单点调色最容易在低层级标题上翻车。

### CM6 的 update() 期间不能读 DOM 布局（2026-10-22）

- **现象**：斜杠菜单要「刚打完 `/` 就弹出来」，但在 `ViewPlugin.update()` 里调
  `view.coordsAtPos()` 会抛错或拿到过期坐标；直接 `queueMicrotask` 也拿不到，
  因为同一帧内还有多次 update。
- **根因**：CM6 明确禁止在 update 过程中读 DOM 布局（布局可能尚未提交），
  `coordsAtPos` 属于布局读取。
- **规避**：把上报**合并成一次微任务**（`pending` 标志 + `queueMicrotask`），
  在同一帧所有 update 结束后统一测量；插件 `destroy()` 时置 `destroyed` 标志，
  微任务里再判 `view.dom.parentNode`，避免组件已卸载还回调宿主。
- **纪律**：任何「随光标移动的浮层」，坐标都必须在 update 结束后测；
  且在 CM6 内部不要直接改 Vue 状态触发同步重渲染。

### 变量遮蔽让块 Widget 静默渲染成空白（2026-10-22）

- **现象**：`::: merged` 容器块在阅读态正常出表格，编辑态只有一个空的
  `.cm-lp-block__body`；无异常、无控制台报错，看起来像「异步渲染没跑完」。
- **根因**：扫描容器的循环里写了 `const text = line.text`，遮蔽了外层的全文
  `text`；块源码因此取成 `text.slice(from, to)`——对小文件直接是空串。
  渲染管线拿空串渲染，自然什么都没有。
- **规避**：局部变量改名（`lineText`），并给块内容加一条最小断言：
  源码非空才建块装饰。
- **纪律**：函数体里已有同名「全文」变量时，禁止再用同名局部变量；
  块 Widget 的空白优先怀疑 `source` 为空，而不是渲染管线。

### 标题的锚点位置不能写死 top: 0（2026-10-22）

- **现象**：h1 的 `#` 位置正确，h2 的 `#` 却浮在标题上方、压在那条分隔线上，
  与文字垂直错开约 24px。
- **根因**：permalink 用绝对定位钉在标题盒左上（`top: 0`），而 h2 有
  `padding-top: 24px`（用来与上节分隔线拉开距离）。绝对定位的基准是 padding box
  的外沿，写死 0 就落在内边距区里。
- **规避**：引入 `--dv-heading-lead`，标题盒自己声明「文字距盒顶多远」，
  `padding-top` 与锚点 `top` 都从同一个变量取值——两者结构上不会再漂。
- **纪律**：任何「绝对定位对齐文字基线」的装饰元素（锚点、行号、引用线），
  位置都要跟着盒模型的实际文字起点走，不能假设文字从盒顶开始。

### 系统保存框挡住了自动化验收（2026-10-22）

- **现象**：导出功能的 CDP 验收脚本挂死，几十秒后超时；日志里没有任何错误，
  产物目录是空的。
- **根因**：`dialog.showSaveDialog` 是 OS 级原生窗口，CDP 既看不到也点不到，
  `await` 永远不返回。而且当次跑的还是**加钩子之前构建的旧产物**，
  所以连「钩子没生效」都看不出来。
- **规避**：主进程支持 `DOCVI_EXPORT_DIR` 环境变量，设置时跳过保存框直接写该目录；
  钩子只改落点、不改产物生成逻辑，验收就能直接断言落盘文件的内容。
  另：**改完主进程代码必须重新构建**再跑验收，`electron-vite build` 的产物不会热更。
- **纪律**：任何依赖原生对话框/原生菜单的功能，验收前先给它准备一个可注入的落点；
  否则自动化的覆盖上限就是「函数被调用了」。

### 六级标题不做配色，只做字号梯度（2026-10-19 用户提问后的取舍）

- **问题**：用户问「1～6 级标题要不要搞特殊化，比如不同颜色或装饰」。
- **实测前提**：全库 78 篇 PRD 的标题使用量 h1=82 / h2=763 / h3=72 / **h4=10 / h5=0 / h6=0**；
  但单篇技术 PRD（如本地预处理文档）里 h4 有 44 处、h3 只有 20 处——**h4 才是实际主力层级**。
- **结论：不上色**。三条理由：① 为 h5/h6 这两种全库零使用的级别做配色是纯成本；
  ② 标题上色会与正文强调色（accent）、链接色抢注意力，读者需二次解码颜色含义；
  ③ 字号 + 间距是排版学标准手段，明暗两套主题下都稳定。
- **落点**：h3 19→20px/650、h4 保持 17px/600 但收窄间距、h5 16px/650 + 字距、
  h6 15px/650 + 更大字距。**旧版 h4/h5/h6 三者同为 17px 完全无法区分**，这是真漏洞，
  已补上递减梯度。
- **纪律**：层级方案先量「各级实际使用量」再定——按教科书六级的漂亮梯度设计，
  很可能在真实文档里只用到中间两级。

### 点一下站内链接就白屏，是三处缺陷叠加（2026-10-24）

- **现象**：正文里点带跳转的文本，整个界面直接空掉，只能重启应用。
- **根因链**：① 阅读视图没接管 `<a>` 点击，`<a href="/guide/x">` 在 Electron 里是真导航，
  窗口跳到一个没有 HTML 的地址 → 白屏；② 接管之后按容器语义把 `/仓库/路径` 的第一段当仓库 id，
  桌面根本没有仓库段 → 「工作区不存在」；③ 渲染管线按平台约定剥掉 `.md`，而桌面 `readDoc`
  要真实文件名 → 「文档不存在」。三处都修完才算通。
- **规避**：链接点击在渲染层统一接管（外链走 `appOpenExternal`，站内发 `navigate`）；
  主进程 `will-navigate` 只放行 `DEV_URL` / `docvi://app/` 作为最后防线；
  站内路径按宿主分支解析（桌面 = 工作区相对路径，容器 = `/<仓库>/<路径>`）；
  无扩展名路径从目录树反查真实文件名，**不要盲目拼 `.md`**（落地页可能是 `索引.md` / `README.md`）。
- **纪律**：凡是「根相对路径」，先问「哪个宿主的根」。

### 分屏同步按源码行，不按滚动比例（2026-10-24）

- **现象**：两侧滚动条进度一致，但内容常常对不上，文档越长错位越明显。
- **根因**：Markdown 源码行数与渲染后高度不是线性关系（代码块、表格、图片各占不同高度），
  按比例同步只是「滚动进度同步」，不是「同一处内容同步」。
- **规避**：块级元素标注 `data-source-line`（0-based 原文件行），编辑区上报顶部可见行号，
  预览按行号定位。**三元状态必须显式建模**：`lineOffset: number | null`，`null` 才是「不对齐」——
  用 0 兼表「无 frontmatter」和「关闭」，会让无 frontmatter 的文档整篇丢行号（本轮真踩到）。

### 顶部工具提示会被 Windows 原生标题栏盖住（2026-10-24）

- **现象**：切换标签页按钮 hover 有 tooltip，DOM 在、`opacity: 1`，用户就是看不见；CDP 测到 `top: 9px`。
- **根因**：`titleBarOverlay` 是原生绘制的 44px 顶部条（右侧约 138px），web 内容画在它下面，
  落进该区域的元素被原生层覆盖，CDP 的可见性判断也看不出来。
- **规避**：顶部 chrome（标题栏、标签栏、标签切换器）的 tooltip 一律 `placement: 'bottom'`；
  验收断言 tooltip 的 `getBoundingClientRect().top` 大于标题栏高度，而不是只断言「存在」。

### 目录树归属不能用 `activeWorkspaceId` 判断（2026-10-24）

- **现象**：去掉启动预扫描后，打开标签页树是空的、正文显示「还没有打开文档」。
- **根因**：`ensureTabReady` 用 `activeWorkspaceId !== tab.workspaceId` 判断「树是否已加载」；
  切回同一工作区时该条件已经相等，于是永远不加载。
- **规避**：树的所有权单独记账（`treeWorkspaceId`）。「当前激活谁」和「当前树属于谁」是两件事，
  凡是缓存类判断都要有独立的归属标记。

### `fetch` 会在客户端规范化 `..`，路径穿越测试打不到服务端（2026-10-24）

- **现象**：分享路由的 `../` 穿越测试期望 404，实际返回 200。
- **根因**：`fetch('http://x/s/a/../../机密')` 在发出前就被 URL 解析器消掉 `..`，
  服务端收到的是合法路径，根本没看到穿越。
- **规避**：路径穿越直接测解析函数（传原始字符串），或用 `http.request` 发原始 path；
  断言「机密内容未被返回」比断言状态码更接近真实目标。

### 全屏铺不满：`max-height` 没覆盖（2026-10-24）

- **现象**：流程图点全屏后画布只铺到视口约 78%，下面留一条纯底色空白。
- **根因**：正文态写了 `max-height: 78vh` 防卡片过高；全屏规则只覆盖了
  `height: auto`，`max-height` 仍然生效——`flex: 1` 撑到 78vh 就停。
  同类还有 overlay 路径下 `margin: 1rem 0` 会从 `fixed + inset` 里再扣掉 32px。
- **规避**：全屏/覆盖层规则必须把「定尺寸属性」成套覆盖（`height` + `max-height` +
  `margin`），只覆盖一半就会留下一个看起来像「渲染失败」的空白条。
  **验收要量内容区底边与视口底边是否重合**，不能只断言 `:fullscreen` 类在。

### 条件渲染的容器里，组合式函数的 `onMounted` 挂不到监听（2026-10-24）

- **现象**：图片灯箱能打开，但滚轮缩放和拖拽完全没反应；`transform` 永远是 `scale(1)`。
- **根因**：`ImageLightbox` 根节点是 `v-if="open"`，组件本身常驻挂载在阅读视图里。
  于是 `useZoomPan` 的 `onMounted` 执行时 viewport 还不存在，`if (!viewport) return`
  把 wheel/pointer 监听全部跳过；之后覆盖层出现了也再没人挂。
- **规避**：需要绑定 DOM 的组合式函数不能只靠 `onMounted`——用
  `watch(viewportRef, …)` 跟随元素出现/替换重新绑定，并记住当前绑给了谁（`boundViewport`），
  卸载时按那个引用解绑。
- **纪律**：「能打开」不等于「能用」。验收要断言实际效果（缩放后 `scale` 变化、
  拖拽后 `translate` 变化），而不是只断言 DOM 存在。

### 首帧改写地址栏会吃掉深链（2026-10-24）

- **现象**：容器里切分支后跳到 `/?branch=dev`，仓库段消失，落回空首页；
  直接打开 `/仓库/文档?branch=x` 也被改写成 `/`。
- **根因**：App 挂载时 `ensureLibrary()` 先激活库标签，标签 watcher 立刻
  `replaceLibraryUrl()` 把深链改写成 `/`；之后 `readRoute()` 读到的已是空路径。
- **规避**：初始路由必须在**任何标签激活之前**读出来存好（`readRoute()` 提前调用），
  应用完再放行地址栏回写（`routeSettled` 门闩）；`replaceLibraryUrl` 也不能
  无条件写 `/`——深链状态下它是错的。
- **纪律**：路由状态与界面状态谁先落地要想清楚。多写一次 `replaceState` 的代价，
  可能是整条深链失效。

### 宿主资产要有自己的地址空间（2026-10-24）

- **现象**：桌面端正文图片全部破图（`naturalWidth === 0`），容器版正常。
- **根因**：渲染管线把图片归一成根相对路径 `/img/a.png`，这是「从内容根伺服」的约定；
  桌面窗口的根是 `docvi://app/`（渲染产物目录），于是图片请求打到产物目录里 404。
- **规避**：桌面新增 `docvi://asset/<工作区 id>/<路径>` 协议，只按**登记过的工作区 id**
  取根，解析后再做 containment；渲染层把「链接前缀」与「资产前缀」拆成两个参数
  （桌面链接无前缀、图片有协议前缀），编辑器实时预览走同一份前缀。
- **纪律**：同一个根相对路径，在不同宿主里可能指向完全不同的地址空间。加宿主时先问
  「这个资源由谁伺服」。

### 宿主缺能力就诚实拒绝，不要给点了必然失败的按钮（2026-10-24）

- **背景**：插件市场想支持远程包，但桌面安装器刻意保持零运行时依赖（没有 `tar`）。
- **做法**：清单只对 `bundled` 来源提供安装按钮；`remote` 条目渲染说明文字并明确拒绝，
  容器读者面返回空市场。宁可少一个入口，也不做一个「看起来能用、点了报错」的入口。
- **纪律**：新增宿主能力入口前，先确认两个宿主都具备该能力；不具备的一侧走 `hostKind` 隐藏。

### 实时预览「光标行不渲染」是刻意的旧取舍，不是能力上限（2026-10-24）

- **现象**：用户报「写个 `#` 按空格后不变 h1，要把鼠标移开那一行才渲染」，问能不能像飞书。
- **根因**：装饰构建里每个样式都带 `if (lineHasCursor(...)) return`——光标所在行整行跳过
  **样式**（不只是跳过标记隐藏），于是刚敲完的那一行永远是纯文本。
- **规避**：把两件事拆开——**样式始终生效**（标题字号、加粗、引用线、列表缩进），
  **只让语法标记的隐藏**受光标影响（光标行保留 `#`、`**`、反引号可见，可以就地改）。
  `style()` / `lineStyle()` 因此不再检查 `lineHasCursor`。
- **纪律**：「光标行退回源码」是编辑器的取舍，不是 Markdown 的能力边界。改这类交互前先
  分清「标记要不要露出来」与「格式要不要生效」——它们可以分开。

### 原始报错不能直接进读者面（2026-10-24）

- **现象**：容器仓库卡片上显示「同步失败：`... credential.helper=store --file=/data/creds...`」。
- **根因**：`sync.error.message` 是 git 的 stderr，原样透传到 `/api/portal`，读者面直接渲染。
  这既暴露了服务器绝对路径与凭证方案，对读者也完全没有信息量。
- **规避**：读者面用 `readerFacingSyncError()` 归一成几类（认证失败 / 网络不可达 /
  仓库或分支不存在 / 其他），完整报错只留在运维面的 `/api/repos`。
- **纪律**：凡是「服务端原始错误」跨出运维边界，都要先分类再输出；报错是给下一个人排查的，
  不是给读者看的现场记录。

### 视觉令牌与品牌标都必须单一源头（2026-10-24）

- **现象**：运维页还挂着紫色旧 logo 与明暗切换按钮，与新版应用完全不像同一产品。
- **根因**：logo 在四处各写一份（图标脚本、标题栏、运维页、docs/assets），配色在运维页
  自成一套（紫色双主题）。改造应用时只改了主界面，运维页那份没人碰。
- **规避**：几何抽到 `scripts/lib/logo.mjs`，`build-icons.mjs` 生成 PNG/SVG 并写出
  `favicon.svg`；运维页 import 同一份 SVG；配色直接对齐 `theme.css` 的 `slate` 令牌，
  运维页固定深色、不再自带主题切换。
- **纪律**：**跨页面重复的视觉资产，第一次就该抽出单一源头**。各写一份的结果不是「风格略有
  差异」，而是改造后仍有一处停留在一年前。
- **附**：品牌构图别用「圆角方块 + 角落小方块/圆点」——这是文档类工具必然撞车的形态
  （实测让另一个 AI 写同类工具，产出一模一样）。辨识度来自结构（错位页、非贯穿扫带），
  不是配色。

### 防护清单不能把被保护的对象写进仓库（2026-10-26）

- **现象**：开源前的敏感词扫描测试里内联了一份禁用词数组，含真实公司名、内网托管商
  域名、私有分支名。门禁本身通过、扫描报「未发现敏感内容」——因为扫描规则里那些词
  被当成「已知规则」跳过了，而它们就明晃晃躺在源码里。
- **根因**：把黑名单当防御手段。黑名单有两个躲不开的毛病：一是写不全，漏一个就静默
  失效；二是**被禁的词必须写进仓库**，等于把要保护的对象抄在门牌上。越认真的防护
  写出的清单越完整，泄露面越大。
- **规避**：所有用词检查改成**白名单**（只列允许出现的域名/路径/标识，新增必须显式
  加一行，顺带强制一次「该不该对外」的判断）或**形态正则**（`(内部|公司)\s*版` 这类
  只描述形状、不含具体值）。需要逐词黑名单时只放 `.scan-deny.local`（已 gitignore）。
- **连带**：公开文档里的本机环境细节同样是泄露——代理端口、个人目录路径、内网地址
  一律写占位符（`127.0.0.1:<port>`），具体值由使用者按自己环境填。
- **纪律**：**门禁的判定依据本身也是公开内容**。写防护代码时先问一句：这段如果被
  贴到项目首页，会不会暴露它想保护的东西？

### 实时预览与阅读态的排版基准必须同源（2026-10-26）

- **现象**：用户反复反馈「实时预览那个错位问题还是有，没完全对准」。肉眼说不出
  具体哪根线，但切模式时整篇文字像被缩放并左移了一点。
- **实测数据**（同一篇文档、同一窗口）：阅读态正文 16px / 行高 28.8px / 文字左
  292px；实时预览 15.5px / 27.13px / 左 284px。H1 阅读态 32px，编辑器算成
  29.45px（1.9em × 15.5px）。列表更糟：阅读态缩进 24px，编辑器零缩进。
- **根因（三处独立偏差叠加）**：
  1. `create-editor.ts` 硬编码 `15.5px` / `1.75`，而 `tokens.css` 里的
     `--dv-content-font-size: 16px` / `--dv-content-line-height: 1.8` **定义了却没人用**
     ——孤儿令牌。视觉常量双源，注定漂移。
  2. 标题字号用 `1.9em`/`1.5em` 相对推算，落在一个错的基准上，误差被放大成 2.5px。
  3. `listDepth()` 返回 **0 基**，而 CSS 只定义 `cm-lp-li-1`…`li-6`，最外层列表项
     落到 `cm-lp-li-0` 无规则匹配，**第一级列表完全没有缩进**（潜伏缺陷，与字号无关）。
- **规避**：编辑器字号/行高改读 `--dv-content-*` 令牌；标题尺寸与 `doc.css` 逐项
  对齐（32/40、24/32、20/30、17/26、16/24、15/22）；`listDepth` 改 1 基。
  行内代码再补 `vertical-align: 0.1em`——0.92em 小字的盒中心比正文低 1.5px，
  逐档实测后取 0.1em 归零。
- **纪律**：**两种渲染模式的排版常量必须来自同一组令牌，禁止各写一套 px/em**。
  判据不是「看起来差不多」，而是切模式前后量同一个元素的 `fontSize`/`lineHeight`/
  `getBoundingClientRect().left` 必须相等。孤儿令牌（定义了没人消费）是双源的前兆，
  一旦发现要么接上、要么删掉。

### 块级 widget 的 DOM 与留白方式决定点击命中（2026-10-27）

- **现象**：用户报「鼠标点在行中间偏下一点就跳到下一行」，并且**稳定复现**；
  同一位置放行中间偏上就正常。光标的 I 形指针要在文本上才准确。
- **量化**：在目标行做 1px 纵向扫描，记录每次点击后光标落在哪一行。修复前：
  带 frontmatter 的文档命中率 68%~89%，不带 frontmatter 的同一篇 100%。
- **根因一：`block: true` 的替换装饰里放了行内元素**。frontmatter 折叠卡用
  `document.createElement('span')` + `display: inline-flex`，而装饰声明为块级。
  CM6 的高度预言机按「一个块」记账，真实 DOM 却参与行内布局，两个口径错开后，
  其后的所有行点击坐标整体偏移。**显示完全正常，只有命中错**，所以极难靠肉眼发现。
  改用 `div` + `display: flex` + `width: fit-content` 后命中率回到 100%。
- **根因二：块 widget 的上下间距用了 margin**。CM6 用 `getBoundingClientRect()`
  量块高，**margin 不计入**盒尺寸。`margin: 0.6em 0` 的 19.2px 不进入记账，
  却真实占据布局高度——块越多、越靠前，累积偏移越大。改 `padding: 0.6em 0`。
- **验证方法（可复用）**：在目标行上按 1px 步长派发 `Input.dispatchMouseEvent`
  点击，每次读 `.cm-activeLine` 的文本与前缀比对，找出「不再命中本行」的偏移量。
  理想分界 ≈ 行高的 50%；明显小于 50% 就是坐标记账出了问题。
- **纪律**：`Decoration.replace({block: true})` 的 widget 必须同时满足
  ①**DOM 是块级**（div/flex，不能用 span/inline-flex）；②**上下留白用 padding**
  （margin 不计入 `getBoundingClientRect`）。这两条都不影响观感，只影响命中。

### 惰性语法树：`syntaxTree()` 返回的是局部树（2026-10-27）

- **现象**：带大 frontmatter 的长文档切到实时预览，正文仍是 `## 标题`、`**加粗**`
  原样，点一下 / 滚动一下才逐渐渲染出来。小文档完全正常，所以看起来「时好时坏」。
- **根因**：Lezer 是**惰性增量解析**，只保证当前视口附近的节点可用。
  `syntaxTree(state)` 返回的就是这棵局部树——实测 45KB 文档只拿到 3134 字符的树。
  用 `iterate` 遍历它，正文里的 ATXHeading / Emphasis / ListItem 根本不存在。
- **⚠️ 更隐蔽的一层**：`ensureSyntaxTree(state, len, budget)` 返回的**返回值**才是
  完整树，它**不会**让后续的 `syntaxTree(state)` 变成完整树。所以必须
  `const tree = ensureSyntaxTree(...) ?? syntaxTree(state)` 然后遍历 `tree`，
  不能「先调 ensure，再继续用 syntaxTree」。
- **代价参考**：45KB 文档 `ensureSyntaxTree` 全文解析实测 12-37ms（预算越大越快复用
  缓存）。这个量级可以接受；真正该避免的是**视口窗口化**——它省下的时间远小于
  它造成的这类静默缺失，本仓已整体删除窗口化，一律全文构建。
