# 组件协议（已退役）

> **状态：2026-11-24 退役。** 本文描述的声明式组件系统已从产品中删除，仅保留这份
> 说明解释「它曾经是什么、为什么删、旧文档怎么办」。

## 它曾经是什么

一套 docvi 专有的文档渲染扩展。作者在 frontmatter 的 `components` 段写 YAML 数据，
正文用 `<at-组件名 data-key="键">` 引用，由内置的通用组件包与音频组件包
提供的 Vue 组件渲染成卡片、流程图、表关系图等视图。

## 为什么删

三条理由，按权重排序：

1. **可移植性与立身之本相反**。用了 `<at-*>` 的文档离开 docvi 就不再可读——GitHub 上是
   裸标签，飞书、语雀、VS Code 预览同理。ADR-0006 曾把它降级为「可选能力」，但只要这套
   系统还在仓库里、还在 MCP 的工具清单上，AI 写任何文档的第一反应都是套组件。
2. **用量证明它不是主路径**。真实业务仓 245 篇文档里只有 11 篇（4.5%）用组件，且主要
   消费者是它自己的演示课程。
3. **核心价值已被通用能力覆盖**。`TableGraph` 用 1032 行解决「mermaid erDiagram 会绞线」，
   实测 mermaid 加一行 `direction LR` 后同一份数据高度从 731px 降到 289px，问题消失。
   流程图、状态机、时序图、表关系全都用 mermaid 表达即可。

## 旧文档怎么办

文档**不需要人工改写**：

- `<at-*>` 是**未知自定义元素**：浏览器不给它任何默认外观，所以那段在阅读视图里是**空白**
  （不是可见的标签文本）。正文语义没有丢——数据仍在 frontmatter 里，只是不再是图形。
  想恢复可读就按下面的对照表换成通用写法。
- `::: merged` 这类容器块会退化成普通段落。

需要迁移时按内容类型换成标准 Markdown：

| 旧的组件写法     | 通用替代                                                                 |
| ---------------- | ------------------------------------------------------------------------ |
| 流程图 / 状态机  | ` ```mermaid ` 围栏（`flowchart` / `stateDiagram-v2`）                   |
| 时序图           | ` ```mermaid ` 的 `sequenceDiagram`                                      |
| 表关系           | ` ```mermaid ` 的 `erDiagram`，加一行 `direction LR` 防绞线              |
| 表设计（逐字段） | GFM 表格：`字段 / 中文名 / 类型 / 约束 / 说明` 五列                      |
| 接口清单         | 每个接口一个 `### METHOD /path` 小节 + 参数 / 响应表格                   |
| 决策记录         | `### 决策` / `### 原因` / `### 证据` 三小节                              |
| 合并单元格表格   | 拆成多张普通表格，或用 ` ```mermaid ` 表达关系                           |
| 交互式图解       | 写独立 `.html`，正文用 `<iframe src="./x.html" sandbox="allow-scripts">` |

完整写法规范见 [内容写法](../engineering/内容写法.md)。

## 插件系统为何保留

插件协议（`plugin.json` + `contributes`）仍然存在，但组件贡献点已没有消费方。现在真正
可用的贡献点只有**主题**（`contributes.themes`）：一整套 `--dv-*` CSS 变量，装好即出现在
设置页的主题网格里（见 `apps/desktop/src/renderer/src/lib/plugin-themes.ts`）。

第三方插件从来没有组件加载器——历史上内置包走静态 import，第三方只有 manifest 校验与
安装流程。所以删除内置组件包没有削弱插件系统的既有能力。
