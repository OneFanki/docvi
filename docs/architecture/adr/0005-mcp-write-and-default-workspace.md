# ADR-0005：MCP 写入能力与内建默认工作区

## 状态

已采纳（2026-11-02）

## 背景

MCP 此前只有六个只读工具。AI 能查组件用法、能检索、能读全文，但**不能写**。而工作区必须由用户在应用里手动添加，首次安装后工作区表是空的——这时 `read_doc` 直接返回「当前没有可读取的文档范围」。

两个缺口叠在一起，结果是「让 AI 帮我写篇文档」这件事在产品里根本走不通：没有落笔的地方，也没有落笔的工具。用户必须先理解「工作区」这个概念、手动选一个目录，才谈得上让 AI 写。

同时有一个设计张力必须先想清楚：**给 AI 写权限，风险不在「能不能写」，而在「会不会写错地方、会不会覆盖掉别人的东西」**。删除的破坏力又比写大一个量级。

## 决策

1. 新增两个 MCP 工具：`list_workspaces`（可写入范围清单）与 `write_doc`（写 Markdown）。
2. `write_doc` 三种模式，语义保守：`create`（默认，只新建，已存在即拒绝）、`overwrite`（**必须**带 `read_doc` 返回的 `baseMtime`，mtime 不匹配即冲突失败）、`append`（文件须已存在）。
3. **不提供删除工具**。
4. 只允许写 `.md` / `.markdown`；路径拒绝绝对路径、`..`、点开头段、扫描排除目录（`node_modules`、`assets` 等）——规则与扫描器共用一份 `doc-paths.mjs`，杜绝「写得进去但树上看不见」。字面校验之外还要对**最深的已存在节点**做 `realpath` 再判工作区根：工作区里的符号链接 / 目录联接能让合法字面路径落到根外。
5. 桌面端播种一个内建默认工作区：`<系统文档目录>/docvi`，只播种一次（settings 记 `defaultWorkspaceSeeded`），用户删掉后不再重建。AI 未指定 `workspace` 时落在这里。
6. **容器端不给写**：不注入 `writeDoc`，工具面自然不含 `write_doc`。
7. 写入失败必须带 `isError: true`——这是工具处理器第一次可以返回错误态，与「查不到」的 `isError: false` 明确区分。
8. **默认工作区是兜底，不是首选**：AI 的落笔优先级固定为「用户明确指定的位置 > 项目规范约定的位置 > 默认工作区」。这条写进 MCP `initialize` 的 `instructions` 与 `list_workspaces` 的返回文本，措辞顺序即优先级。
9. **默认工作区不可移除**：界面上不提供移除入口，主进程 `workspaceRemove` 对它直接返回 `E_FORBIDDEN`。
10. **默认工作区默认按 mtime 排序**：最新修改的排最上面。排序方式是工作区级偏好（`treeSort`），可在树工具栏切回 `manual`。

## 原因

1. **默认工作区把「配好才能用」变成「装好就能用」**：用户说「写篇文档」，AI 直接落笔到 `文档/docvi`，用户在应用里立刻看到（磁盘实时跟随会自动刷新树）。不需要先理解工作区概念。
2. **保守写入语义比权限开关更有效**：`create` 默认 + `overwrite` 必须带 mtime，覆盖用户手写文档需要显式两步（先读再写），而且期间被别人改动会失败。这比一个「允许 AI 写入」的总开关更能防住意外——开关只区分「能/不能」，不区分「写错」。
3. **mtime 冲突判定复用编辑器同一套语义**：编辑器保存本来就这么判（`fs-write.ts`），写入层再发明一套只会让两边行为不一致。
4. **路径规则必须与扫描口径共用**：这是「写得进去但看不见」的唯一防线。两套规则各自演化时，AI 会成功写入一个用户永远看不到的文件，且没有任何报错。
5. **不提供删除**：删除的破坏力远超写（回收站之外的永久删除、目录递归删除）。MCP 开这个口子，收益远小于风险；需要删除时用户自己在应用里操作。
6. **容器不写**：`deployer` 的工作树是构建用的临时副本，`git.mjs` 没有 commit/push。写进去既不回传远端仓库，也会在下次构建时被覆盖——声明一个兑现不了的工具就是骗 AI。
7. **失败必须 isError**：若写失败被当成普通文本返回，AI 会向用户报告「已写入」，而磁盘上什么都没有。这种静默失败比报错难排查一个量级。
8. **兜底不等于默认首选**：没有明确指令时「有个地方能写」是好事，但一旦 AI 把它当成习惯落点，用户说的「写到 X」就会被无视。用一句固定措辞的优先级声明把它钉死，比在每个工具描述里重复说明更可靠——`instructions` 是 AI 连上就会读的唯一入口。
9. **不可移除保护的是「AI 有地方可写」这个能力，不是这个目录**：用户真不想要它时，删掉 `<文档>/docvi` 目录即可；拒的只是「移除登记」——那张卡片一删，`write_doc` 就退回到「无法确定写到哪里」，而用户不会把这个后果和一次顺手点击联系起来。
10. **默认工作区用 mtime 排序**：它是 AI 随手写的地方，文档名通常没有规律（往往是「XX 设计」「XX 排查记录」这类），按名字找不如按「最近改的」找。普通工作区保持 `manual`——那些库的 `order` / 命名是有编排意图的，不该被默认打乱。

## 被否方案

| 方案                                                 | 否决原因                                                                                                                 |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 通过 HTTP 文件接口（`POST /docs`）暴露写入，不走 MCP | 与「MCP 是写文档者的唯一接入点」冲突；多一套协议面就要多一套鉴权、文档与测试，且 AI 客户端还得额外配置                   |
| 加一个「允许 AI 写入」总开关                         | 开关只区分能/不能，防不住「写错地方」「覆盖别人的改动」；而保守语义本身就把风险压在可控范围，多一个设置项只增加心智负担  |
| AI 只能写默认工作区，其他工作区只读                  | 用户明确说「写到某个已有工作区」时做不到，等于把便利功能做成半成品；风险靠写入语义控制，不靠范围限制                     |
| 容器端实现写入（新增 git commit + push）             | 容器是多仓库编排、分支即内容版本，写入必须走「提交 → 触发构建 → 发布」的完整链路；这是独立产品决策，不是补一个工具的量级 |
| 提供 `delete_doc`（含回收站）                        | 删除不可逆风险远超写入，且 Electron 的 `trashItem` 只能在主进程调用、服务进程够不着；要做也必须先有完整的权限模型        |
| 默认工作区放 `%APPDATA%/docvi/workspace`             | 用户平时找不到它；卸载或清缓存会连文档一起丢。系统「文档」目录能随 OneDrive / 备份工具同步，卸载也不影响                 |
| 每次都检查默认工作区是否存在、不存在就重建           | 用户删掉它就是不想要，重启再建出来是骚扰。用 settings 记「已播种」区分「从没建过」与「用户删了」                         |
| 默认工作区与普通工作区长得一样（无从区分、可移除）   | 它会成为 AI 的兜底落点，用户必须看得出「这个不一样」；可移除则一次误点就让 AI 失去落笔处，且后果延迟到下次写入才暴露     |
| 靠「AI 自觉」遵守用户指定的位置，不加优先级声明      | 默认工作区越方便，AI 越容易顺手写进去。工具的便利性本身就是偏移力，必须用明确措辞抵消，不能指望模型自行权衡              |
| 全局设置一个排序方式（不分工作区）                   | 普通文档库的 `order` / 命名编排是有意的，被整体改成 mtime 会打乱读者预期；排序是「这个库怎么找文件」的偏好，应按库区分   |

## 后果

- **默认工作区会出现在用户的文档目录里**（`<文档>/docvi`）。这是用户可见的行为变化，升级后首次启动就会发生，需在 CHANGELOG 里说明。
- AI 获得了对所有已登记工作区的写权限（受保守语义约束）。愿意更严格的用户可以删掉不想让 AI 写的工作区——工作区表就是权限面。
- 桌面端 MCP 请求体上限从 256KB 提到 2MB（单篇 1MB + JSON 开销）。容器端仍是 256KB（无写工具）。
- `packages/server` 新增 `doc-paths.mjs`（路径规则）、`doc-write.mjs`（写入语义）、`fs-atomic.mjs`（原子写）。桌面 `fs-write.ts` 与 MCP 写入共用原子写实现。
- `read_doc` 的返回文本多了一个 `mtime` 字段（不会破坏既有客户端，是附加信息）。
- 工具面从 6 个变成 8 个（桌面）/ 7 个（容器）。所有写死数量的文档、i18n 文案、测试断言都需同步。
- **`WorkspaceEntry` 新增两个字段**：`default`（派生、不落盘）与 `treeSort`（落盘、工作区级偏好）。`workspaceList` 返回的条目会带 `default`；`treeList` 依据 `treeSort` 决定顺序。
- **`workspaceRemove` 对默认工作区返回 `E_FORBIDDEN`**：任何调用方（界面、命令面板、将来的脚本）都要准备好处理这个错误码。
- 目录树排序改了实现分层：`scanDir` 需要为每个节点读 `stat.mtime`。这给扫描加了一次 stat/节点——实测在几百篇量级的库上无感，但树特别大（数千文件）时重扫会略慢，属可接受成本。
