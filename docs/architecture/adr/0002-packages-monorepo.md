# ADR-0002：仓库改为 packages/ 多包结构

## 状态

已采纳（2026-10-19）

## 背景

现状是「壳 / 部署器 / Tauri 宿主 / 插件」平铺在仓库根，边界靠约定维持：

- `shell/` 没有自己的 `package.json`，依赖全部挂在根，壳用到的库与服务端用到库混在一起，无法判断某依赖属于谁。
- `deployer/` 有独立 `package.json` 与独立 lockfile，但它与根共享一部分运行时语义（索引生成、分享），实际是隐式耦合。
- `plugins/` 已在 workspace 内，但插件协议与壳的类型定义分散在两处。
- 新宿主（Electron）若继续平铺，根目录将出现第二个 `desktop/` 与第三套依赖声明。

## 决策

改为 **`packages/` 多包 workspace**：`shell` / `server` / `desktop` / `plugins-base` / `plugins-audio`，各自有 `package.json` 与显式依赖；根只留编排脚本与共享开发工具。

## 原因

1. **依赖归属显式化**：每个包声明自己用什么，服务端不再被壳的依赖污染，打包体积与安全审计可定位。
2. **边界可守护**：包间依赖方向可以静态扫描（`scripts/check-boundaries.mjs`），而不是靠 code review 记。
3. **插件与平台解耦**：预设插件包成为正式 workspace 包，第三方插件按同一形态独立仓发布，本地预设只是「恰好同仓」。
4. **对齐长期开源惯例**：贡献者熟悉 `packages/*` 布局；新增宿主 / 新插件包不需要动根结构。

## 被否方案

| 方案                                                     | 否决原因                                                         |
| -------------------------------------------------------- | ---------------------------------------------------------------- |
| 维持平铺，只补 `package.json`                            | 依赖仍可跨目录随意 import，边界不可守护；新增宿主时问题重演      |
| 拆成多个独立 git 仓（shell / server / desktop 各自成仓） | 单维护者场景下跨仓改动成本过高；版本对齐、联调、发布都要额外机制 |
| 用 Nx / Turborepo 一类编排器                             | 当前包数量与构建复杂度不足以抵消引入成本；pnpm workspace 已够    |

## 后果

- **必须**：`pnpm-workspace.yaml` 纳入 `packages/*`；`plugins/` 在迁移期保留并在 B2 后并入 `packages/plugins-*`。
- **必须**：`commitlint` 的 scope 自动发现覆盖 `packages/*` 目录名。
- **必须**：`scripts/check-boundaries.mjs` 守护依赖方向；新增包时同步 scope 发现与边界规则。
- **代价**：迁移期存在两套路径（`plugins/` 与 `packages/plugins-*`），构建脚本需兼容；迁移完成后删除旧路径。
