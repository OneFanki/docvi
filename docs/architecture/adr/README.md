# ADR（架构决策记录）

> 决策是项目的「意图层」：ADR 记录**为什么**，代码与文档记录**是什么**。新决策必须写 ADR，禁止只口头讨论或只写进代码注释。

## 模板

```markdown
# ADR-00XX：<决策标题>

## 状态

<已采纳 / 提议 / 已废弃（被 ADR-00YY 替代）>

## 背景

<为什么需要这个决策：现状、痛点、触发因素>

## 决策

<最终选择，一句话说清>

## 原因

<选择它的理由，逐条列出>

## 被否方案（必填）

| 方案         | 否决原因       |
| ------------ | -------------- |
| <备选方案 A> | <为什么不选 A> |
| <备选方案 B> | <为什么不选 B> |

## 后果

<采纳后带来的义务、约束、后续工作>

## 修订记录

| 日期       | 内容     |
| ---------- | -------- |
| YYYY-MM-DD | 初始采纳 |
```

## 规则

1. **被否方案必填**：否决理由才是防止未来重复争论（包括 AI 重新提出同样方案）的关键资产。
2. 一个 ADR 只记一个决策；多个独立决策拆多个 ADR。
3. 决策被替代时，旧 ADR 状态改「已废弃」并指向新 ADR，不删除。
4. 补充历史 ADR 的缺失段落时，在段落标题标注「（补充于 YYYY-MM-DD）」，不得改写原始决策。
5. 编号递增，不复用。
6. 功能内的关键决策在 SPEC 的「关键决策」节概述即可；只有**重大跨模块决策**才写 ADR。
