# 订单中台

一个虚构电商的订单系统。这份文档演示「Markdown 原文 + 浏览器端渲染 + 声明式组件」
能做到什么程度——正文里可以直接写流程图、状态机、表关系图、接口清单，
不需要另开一套构建流程，也不需要导出图片。

## 从哪读起

- **[系统概览](开始/系统概览.md)** —— 整体链路与关键指标
- **[订单状态机](设计与实现/订单状态机.md)** —— 一笔订单会经历哪些状态
- **[表结构设计](设计与实现/表结构设计.md)** —— 五张表，谁引用谁
- **[接口清单](设计与实现/接口清单.md)** —— 对外接口与不变量
- **[交付计划](交付/交付计划.md)** —— 排程与上线前检查

## 这份文档的性质

**Markdown 是唯一事实源。** 所有图表都由 frontmatter 里的结构化数据渲染：
没有图片、没有单独的绘图工具，改数据即改图，diff 里看得见改了什么。

**零构建。** 正文改完刷新就变，没有编译等待。

**可被 AI 读。** 同一份内容通过 MCP 暴露给支持 Streamable HTTP 的 AI 客户端，
问「订单为什么不能回退状态」它能直接引用这篇文档回答。
