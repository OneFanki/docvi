# 对账口径

对账只回答一个问题：**平台记的钱和渠道记的钱，差在哪一笔**。下面这些约定都是为了让
差额在出现的那一刻就能归因，而不是月底对着一堆数字猜。

## 三条口径

1. **金额一律取下单快照**。商品后来调价、优惠后来失效，都不回写历史订单；否则同一笔
   订单在两天的报表里金额不同，差额无法归因。
2. **支付单是唯一可信的流水来源**。订单上的 `paid_amount` 只是索引，出现分歧时以支付单
   的 `external_id` 与金额为准，重新汇总。
3. **关单不等于退款**。超时关单只回滚库存与状态，钱的事由退款流程单独处理，两条流水
   分开记账。

## 差额的处理顺序

> 先确认差额真实存在，再判断它是否可解释，最后才谈补录。
> 跳过前两步直接补数，会把「口径错误」变成「数据错误」。

第一步永远是按渠道流水号对齐，先找出单边账：

```sql
select channel, external_id, amount
from payments
where created_at >= :day
  and status = 'paid'
order by channel, external_id
```

对不上的部分再去查回调日志。仍然解释不了的，登记成待查项，不直接改数——改数会把
「不知道原因」变成「不知道曾经改过」。
