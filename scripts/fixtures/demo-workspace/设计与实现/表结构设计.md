# 表结构设计

订单域五张表。**金额与价格全部是快照**——商品调价不影响历史订单，这是对账的前提。

**订单域表关系**

| 表名          | 中文名 | 职责                                       |
| ------------- | ------ | ------------------------------------------ |
| `orders`      | 订单   | 订单主表：金额与状态在此维护。             |
| `order_items` | 订单项 | 订单里的商品行，价格是下单时的快照。       |
| `payments`    | 支付单 | 一次支付尝试一行；重复支付由唯一索引拦住。 |
| `products`    | 商品   | 只作被引用的上游示意。                     |
| `users`       | 用户   | 只作被引用的上游示意。                     |

**外键关系（目标表以实体代码为准）**

- `orders.user_id`：下单用户
- `order_items.order_id`：所属订单
- `order_items.product_id`：商品
- `payments.order_id`：所属订单

### orders（订单）

订单主表：一次交易的根。

| 字段         | 中文名   | 类型          | 约束 | 说明                             |
| ------------ | -------- | ------------- | ---- | -------------------------------- |
| `id`         | 主键     | bigint        | PK   | 全局有序 ID                      |
| `user_id`    | 下单用户 | bigint        | FK   | 关联用户中心                     |
| `status`     | 状态     | varchar(16)   | 索引 | pending/paid/shipped/done/closed |
| `amount`     | 订单金额 | decimal(10,2) |      | 下单时快照，不随商品调价变化     |
| `created_at` | 创建时间 | datetime      | 索引 | 按天统计的基准列                 |

### order_items（订单项）

订单里的商品行：数量与成交价快照。

| 字段         | 中文名   | 类型          | 约束 | 说明               |
| ------------ | -------- | ------------- | ---- | ------------------ |
| `id`         | 主键     | bigint        | PK   |                    |
| `order_id`   | 所属订单 | bigint        | FK   | 订单删除时级联清理 |
| `product_id` | 商品     | bigint        | FK   |                    |
| `quantity`   | 数量     | int           |      |                    |
| `price`      | 成交价   | decimal(10,2) |      | 下单时的价格快照   |

### payments（支付单）

每次支付尝试一行，回调按它做幂等。

| 字段          | 中文名     | 类型        | 约束 | 说明                     |
| ------------- | ---------- | ----------- | ---- | ------------------------ |
| `id`          | 主键       | bigint      | PK   |                          |
| `order_id`    | 所属订单   | bigint      | FK   |                          |
| `channel`     | 支付渠道   | varchar(16) |      |                          |
| `external_id` | 渠道流水号 | varchar(64) | UK   | 唯一索引，重复回调即撞键 |

## 两条硬规则

1. 库存扣减与订单落库在**同一个事务**内，否则会超卖；
2. 支付单在 `external_id` 上有唯一索引，重复回调撞键即视为已处理。

## 为什么金额存快照

`orders.amount` 与 `order_items.price` 都是下单那一刻的值，不是外键引用现价。
商品调价后，历史订单的金额必须保持原样——否则同一笔订单在两天的报表里金额不同，
对账时无法解释差额来自「算错」还是「改了价」。

代价是快照会冗余一份数据，但这个冗余是刻意的：它是历史事实，不是缓存。
