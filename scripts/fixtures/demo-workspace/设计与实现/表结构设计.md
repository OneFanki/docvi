# 表结构设计

订单域五张表。**金额与价格全部是快照**——商品调价不影响历史订单，这是对账的前提。

<at-table-tabs data-key="tabs"></at-table-tabs>

## 两条硬规则

1. 库存扣减与订单落库在**同一个事务**内，否则会超卖；
2. 支付单在 `external_id` 上有唯一索引，重复回调撞键即视为已处理。

## 为什么金额存快照

`orders.amount` 与 `order_items.price` 都是下单那一刻的值，不是外键引用现价。
商品调价后，历史订单的金额必须保持原样——否则同一笔订单在两天的报表里金额不同，
对账时无法解释差额来自「算错」还是「改了价」。

代价是快照会冗余一份数据，但这个冗余是刻意的：它是历史事实，不是缓存。
