# 评审记录

一次设计评审要留下的东西：**决定了什么、为什么**、还有哪些风险没关、这次改了哪些地方。
这三类信息在会议纪要里通常混成一段散文，事后没人能确认「当时是不是考虑过另一个方案」。

## 没关掉的风险

风险清单刻意区分「本方案已处理」与「待独立处理」——后者不是遗漏，是明确记账：
它被看见了，并且有人负责。

<at-risk-list data-key="risks"></at-risk-list>

## 改动范围

改动清单按「新增 / 变更 / 移除」分类，并标出受影响的模块。评审时先看这一块，
就知道这次动了多大面积。
