把 Markdown 目录变成
可读、可搜、可交互的文档站。

图表、状态机、表设计、接口清单都是正文的一部分。

不导出图片，不另开绘图工具。数据写在 frontmatter，正文一个标签引用它，浏览器现渲染成图—— 改数据即改图，git diff 里看得见改了什么。

下载最新版 看看能做什么

桌面应用打开本机任意文件夹就是文档库；同一份界面也能跑在容器里，当团队共享的只读文档站。 没有账号体系、不上传内容、不需要登录。

Why

Markdown 写到一定程度就不够用了

一个订单状态机，用文字描述清楚要写三段，读者还得自己在脑子里画图；一段接口约定， 参数表和「哪条规则不能破」混在一起，改的时候没人能确认有没有碰到红线。

01

图是图片的时代

改图 = 重新导出

成熟的方案是文档框架 + 绘图工具 + Diagram-as-Code 服务。代价是图成了 png： 改图要重新导出，图与正文的措辞对不上没人发现，图里的数据也改不了。

02

图也是正文

改数据即改图

docvi 把图表数据写进文档头部，正文只放一个引用标签。图在浏览器里现渲染， 所以它永远和正文同一版，评审时 diff 里能看到数据改了什么。

03

Markdown 是事实源

零编译 · 零迁移

不用把内容搬进数据库或私有格式。任意目录配上可选的一份配置就能读， 换个编辑器打开还是同样的 Markdown。

Editor

编辑时看不见 Markdown 语法

**加粗** 直接显示成加粗，## 标题 就是一个标题。 鼠标移到行首会浮出级别徽标，点开就能改；选中文字浮出工具条，都是原地改语义。

模式 用途
阅读 只读渲染结果，最接近读者看到的
实时预览 所见即所得，隐藏标记（默认）
源码 纯 Markdown，等宽字体，可切换折行
分屏 左源码右渲染，改左边右边立刻变
Structure

把结构画出来，而不是描述出来

节点、连线、标注都是数据。分支、回边、跨行的长边由布局引擎处理——它做三件事： 断环识别、最长路径分层、重心排序降交叉。

  • 还有这些组件 时序图、调用树、代码走读（行号 + 分步高亮）、决策卡、风险清单、改动清单、 验收清单、指标卡、时间线、diff 视图、合并单元格表格，以及一个可以塞任意 自包含 HTML 的沙箱容器。全部 24 个。
  • Markdown 表达不了的也能写 合并单元格这类结构走 ::: merged 容器，里面写 YAML， 渲染成带 rowspan / colspan 的表格——但 Markdown 仍然是事实源。
Features

两种用法，一份界面

差别只在宿主能力由谁提供：桌面由 Electron preload 提供，容器由一层 HTTP 适配层提供。 界面不另写第二套——做不到的能力自动隐藏，不会露出点了必然失败的按钮。

桌面应用

  • 编辑 四种模式、选区工具条、表格可视化编辑、斜杠插入组件
  • 文件 新建 / 重命名 / 移动 / 复制 / 删除，拖放 .md 打开，文件关联
  • Git 克隆、切分支、拉取；平台自持副本，绝不碰你的工作目录
  • 多标签 标签是内容源 + 路径 + 滚动位置，不持有 DOM；可新开、复制、重排
  • 查找 Ctrl+F 文档内查找，命中高亮与计数
  • 本地服务 MCP 端点与临时分享；关窗口留托盘，服务继续跑

容器站点

多仓库编排、分支切换、索引刷新队列、门户——但没有本地磁盘、git 客户端与插件安装。 运维面在 /_/admin，由 OPS_TOKEN 门禁； 没配这个变量时运维面整体关闭，只剩门户与文档站可访问。 

cp .env.example .env      # 填 OPS_TOKEN（必填）
docker compose up -d --build
# 打开 http://localhost:8080/_/admin
# → 添加 Git 仓库 → 自动克隆并首次刷新索引
AI

让 AI 读你的文档，而不是凭印象编

本地服务暴露一个 MCP 端点（Streamable HTTP），把你的工作区内容交给支持它的 AI 客户端。 工作区增减会自动同步到服务。 

http://127.0.0.1:<port>/mcp
  • 六个工具 list_plugins · list_components · get_component_docs · get_plugin_docs · search_docs · read_doc
  • 默认只绑回环地址 端点与令牌在「设置 → 对外访问」里，一键复制成一整段客户端配置； 显式打开「允许局域网访问」才会对同网段可见。

临时分享

想把一篇文档发给同事看，不用提交、不用部署：在文档页或工作区卡片点「分享」， 拿到一条 /s/<id>/ 链接。

分享是路径代理，不是复制：链接每次读的都是磁盘上的当前文件， 删掉或改了立刻生效；停用分享或关掉服务，链接立刻失效。 链接 id 是 64 bit 随机值，链接即权限——没有账号体系，也不打算有。

两条硬边界

只读。分享出去的链接不能改你的文件，查看者永远只读。

不复制。没有「上传」这个动作，所以服务器上不会多出一份副本， 也就不存在「忘了删」的问题。

Install

安装

从 Releases 下载安装包。发布产物没有代码签名（个人开源项目不购买证书）， 首次运行系统会提示来源不可信，属于预期行为。

平台 首次运行
Windows SmartScreen 点「更多信息」→「仍要运行」；浏览器下载时可能需要手动保留
macOS 右键应用 →「打开」确认一次

当前为 0.x 阶段，数据格式与接口可能变化。

自己构建

要求 Node.js ≥ 22.18 与 pnpm 12（corepack enable 即可）。

pnpm install
pnpm docvi:dev        # 开发态（Electron + Vite 热更新）
pnpm verify           # 全量门禁（CI 跑的是同一个）
pnpm docvi:build      # 构建产物 → apps/desktop/out
pnpm docvi:dist       # 出安装包 → apps/desktop/release
Non-goals

明确不做什么

  • 不做云端协作。没有账号体系、没有实时协同、没有评论。 文档的真相源是 git。
  • 不做所见即所得的富文本编辑器。Markdown 原文永远是事实， 编辑器只是不让你背语法。
  • 不做通用绘图工具。组件是给「讲清楚一件事」用的， 不是 Freeform 画布。
  • 不做 WYSIWYG 导出。不生成 PDF / Word。要分发就发链接。
