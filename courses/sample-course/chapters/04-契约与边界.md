掌握主流程与核心实现后，本章回答两个问题：**为什么这样设计**，以及**哪些内容被刻意省略**。

## 关键设计决策

| 决策 | 原因 |
| --- | --- |
| 用 `WeakMap` 存依赖表 | 不需要手动清理已回收对象的依赖，避免内存泄漏 |
| 用 `Proxy` 而非 `Object.defineProperty` | 可拦截动态新增属性、数组索引，且天然支持嵌套 |
| 依赖集合用 `Set` | 同一 effect 对同一属性只登记一次，天然去重 |
| 先清理、再重收集 | 依赖始终与「当前实际读取」一致，避免陈旧触发 |

## 常见误区

- **「修改一定会触发更新」** —— 只有「被 track 过的属性被修改」才触发；你没读过它，改了也不会通知你。
- **「effect 每次都是全新依赖」** —— 恰恰相反，它维护的是同一份依赖，靠 `cleanupEffect` 保证内容正确。
- **「响应式就是监听器」** —— 不要漏掉「收集（track）与触发（trigger）配对」这一半；没有收集的触发是无意义的。

## 本教程刻意省略的内容

这些不是不重要，而是它们适合在掌握主骨架之后再展开：

- `ref` / `computed` 的具体实现与惰性求值、脏值检查；
- 批量调度与 `nextTick`（多个依赖变更合并为一次渲染）；
- 深层嵌套（`reactive` 的递归 `Reflect.get`）与 `toRaw` / `markRaw` 等工具；
- Vue 真实源码的 `branches`、`scheduler`、`flush` 时序等工程细节。
