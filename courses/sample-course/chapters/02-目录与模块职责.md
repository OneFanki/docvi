# 02 · 目录与模块职责

<at-tutorial-shell data-key="tutorialShell1"></at-tutorial-shell>

教学片段把「迷你响应式模块」整理成下面的目录。**这是教学结构**，由教程作者静态定义，作用是让你先知道「每个位置负责什么」，再一头扎进源码就有坐标感了：


<at-file-tree data-key="fileTree2"></at-file-tree>

## 各文件职责速记

| 文件 | 职责 |
| --- | --- |
| `reactivity.ts` | 数据平面：`reactive()` 与 `track()` / `trigger()` |
| `effect.ts` | 副作用平面：`ReactiveEffect` 与「清理后重收集」 |
| `ref.ts` | 把单一值包成响应式（`value` 读写） |
| `computed.ts` | 惰性求值的派生值，本质是带缓存的 effect |
| `store.ts` / 组件 | 业务侧：只读写响应式数据，不关心实现细节 |

## 两个平面的边界

- **数据平面**回答「数据变化时谁被通知」——`track` 收集、`trigger` 触发；
- **副作用平面**回答「谁会被通知、如何被运行」——`ReactiveEffect`、依赖清理。

两个平面互相配合：`track` 需要知道「当前 effect 是谁」（副作用平面的栈），
`effect.run()` 需要知道「往哪里登记」（数据平面的依赖表）。文件边界清楚了，读代码时心里就有地图。
