# 03 · 契约、数据模型与证据

<at-tutorial-shell data-key="shell"></at-tutorial-shell>

六个「契约 / 数据 / 证据 / 排查」类组件——示意域为通用的「订单系统」，不含业务特化。

> 本章是**声明式写法**的活样例：全部组件数据放 frontmatter 的 `components` 段
> （`kind` 决定组件、其余键与组件 props 同名），正文用 `<at-组件名 data-key="键">`
> 引用——无 script setup、无业务 JS，任何标准 markdown 渲染器都能读到这段结构化数据。

## 契约：模块的输入 / 输出与不变量

「谁喂谁、谁能改什么」的口径用 ApiContract 沉淀——比裸签名更能讲清时序与责任。它面向**内部模块 / 函数边界**的契约（下例是扫描器模块，不是网络接口）；对外 HTTP 端点的清单一律用下一节的 EndpointList。不变量 `kind: 'must'` 正向保证、`must-not` 反向约束。

<at-api-contract data-key="scanner"></at-api-contract>

## 接口清单：折叠看全貌、按需展开详情

写接口文档时读者是先问「有哪些接口、各自干什么」，再问「这个接口的参数长什么样」。EndpointList 因此**默认全折叠**：折叠态一行一个端点（方法徽章 + 路径 + 一句话职责 + 权限门槛），点击行才展开契约详情（入参 / 出参关键字段 / 不变量）；顶部有方法筛选条，行右侧徽章标注权限门槛，已退役端点划线标记（本例最后一个）。展示程度刻意克制：**展开态只放契约承诺（关键字段 + 语义约束），不抄全量 DTO**——完整 schema 以 OpenAPI / 代码为准，避免双源漂移。没有细节可展开的端点（本例 `GET /api/orders/:id`）不显示展开箭头。

<at-endpoint-list data-key="orderEndpoints"></at-endpoint-list>

## 表关系：分层表卡 + 外键连线

表多、关系密时，手写 mermaid erDiagram 常会绞在一起（自动布局不可控）；TableGraph 用**分层布局**解决：引用方在左、被引用方在右（列 = 依赖深度），连线只从左往右流；每张表只放**关键字段**（主键/外键/状态等要点，不列全量），每条关系画成**连线**，锚点连到具体字段行（`orders.user_id → users.id`），线中点标注语义。悬停表卡高亮相关连线、悬停连线高亮两端卡片与字段行、点击连线跳到被引用表（长页里不用四处找）。字段全量在下一节的 TableTabs——**概览看这里，明细看那里**。

<at-table-graph data-key="graphOverview"></at-table-graph>

## 表设计：一表一页签 + 表间关系

表设计用 TableTabs：上面是页签、每页签一张完整字段表（字段名 / 中文名 / 类型 / 键 / 业务说明）；传 `relations` 时底部渲染表间关系脚注——跨表引用一眼看全，且不随页签切换、不随内容滚动。单表场景同样用它（只有一张表时不渲染页签栏）。组件限高（一屏内）、表格在内部滚动——横向滚动条不用把页面滚到底才看得到；页签固定在滚动区之外，滚内容时页签不动；右上角可全屏（页签栏一起放大）。

<at-table-tabs data-key="orderTabs"></at-table-tabs>

## 证据：教学片段 ⇄ 项目快照

平台原则是「片段 = 整理 + 教学注释版，不逐行搬源码」——EvidenceNote 把抽象与快照显式挂起来，`teaching-scope` 声明覆盖边界，避免读者误以为片段就是完整源码。

<at-evidence-note data-key="evidence"></at-evidence-note>

## 调试表：按症状筛选

症状大多一眼看不出来，先按环节 / 现象收窄再对症下药。数据里写 `severity: error` 这样的预筛字段（或标签属性传 `severity`）可以初始过滤（本例不传，展示全表）。

<at-debug-table data-key="debug"></at-debug-table>

## 合并单元格表格：原生 Markdown 表达不了的排版

普通 Markdown 表格的每个格子都必须独立写出，「一格跨两行」表达不了。这类排版用
`::: merged` 结构化块：容器内是 YAML，用 `rowspan` / `colspan` 描述合并关系，渲染成
真正的合并单元格。它**不走 frontmatter 的 components 段**——数据就在正文里，没有
装插件的阅读器也读得懂这段 YAML。

::: merged
title: 发布节奏
columns: [阶段, 负责人, 状态]
caption: 阶段跨多行用 rowspan 合并；「联调」跨两列用 colspan。
rows:

- [{ cell: 设计, rowspan: 2 }, 张三, 已完成]
- [李四, 进行中]
- [{ cell: 开发, rowspan: 2, head: true }, 王五, 已完成]
- [{ cell: 联调, colspan: 2 }, 未开始]
:::

写的时候记住一条：被 `rowspan` 占住的列在后续行里**不再出现**——上面第二行只写两个
单元格，因为第一列已经被「设计」占住了。
