# 04 · 演进与图解

<at-tutorial-shell data-key="tutorialShell1"></at-tutorial-shell>

两个「增量与图解」类组件：一个回答「什么变了」（DiffView），一个负责 Mermaid 画不动时的自由画布（HtmlEmbed）。

> 页面数据统一放在本章 frontmatter 的 `components` 段（`kind` 决定组件、其余键与组件 props 同名），
> 正文用 `<at-组件名 data-key="键">` 引用——零 script setup，任何标准 markdown 渲染器都能读到这段结构化数据。


## 变更：只保留讲清变化的行

重构 / 演进 / 修复类讲解，要点是「什么变了」而周边形状读者已经知道时，用 DiffView 代替整段代码——只保留讲清变化所需的行（上下文行超过定位所需的量就该删）。示例：导出模块删掉内联的字节格式化，改为复用工具函数。

<at-diff-view data-key="diffView2"></at-diff-view>

diff 里最值得注意的往往是**保留不变的行**：调用处的形状（`rows.reduce(...)` 那段统计）原样不动，换掉的只是格式化函数背后的实现来源——「真相源收敛、调用方零改动」就是这么做到的。

## 图解：Mermaid 装不下的密集概念

多面板对比、状态对照、需要交互演示的图解，Mermaid（含平台内置的放大浮层）表达不了时用 HtmlEmbed：写一个自包含 HTML（内联 CSS/JS、零外部请求）内嵌进 sandbox iframe，脚本可交互但读不到页面 DOM / 存储。示例：同一场故障在 15 秒观察窗内的两种重试策略对比——点「重放对比」看重试点逐次出现。

<at-html-embed data-key="htmlEmbed3"></at-html-embed>

> 使用纪律：先确认 mermaid / DiffView / FileTree 确实表达不了再写 HTML 图解；一个图解聚焦一个概念。用法与安全边界见仓库 `docs/architecture/组件协议.md`。
