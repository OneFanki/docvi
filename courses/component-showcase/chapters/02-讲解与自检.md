      /** 把字节数格式化为易读字符串（1024 进制，保留一位小数） */
      export function formatBytes(bytes: number, fractionDigits = 1): string {
        if (bytes < 1024) return `${bytes} B`

        const units = ['KB', 'MB', 'GB', 'TB']
        let value = bytes
        let unit = ''
        for (const candidate of units) {
          value /= 1024
          unit = candidate
          if (value < 1024) break
        }
        return `${value.toFixed(fractionDigits)} ${unit}`
      }

# 02 · 讲解与自检

<at-tutorial-shell data-key="tutorialShell1"></at-tutorial-shell>

四个「讲解 / 决策 / 自检 / 下一步」类组件，仍以构建管线为示意域。

> 页面数据统一放在本章 frontmatter 的 `components` 段（`kind` 决定组件、其余键与组件 props 同名），
> 正文用 `<at-组件名 data-key="键">` 引用——零 script setup，任何标准 markdown 渲染器都能读到这段结构化数据。


## 代码块：带文件名与出处的 CodeBlock

Markdown 原生代码围栏没法给代码块附「文件名 + 出处徽标」。要给每段代码标明「建议路径 / 来源」时用 CodeBlock（`:line-numbers` 可选）。

<at-code-block data-key="codeBlock2"></at-code-block>

## 决策卡：为什么这样做

关键设计决策用 DecisionCard 沉淀——每条「决策 + 原因 +（可选证据）」，`kind: 'why'` 正向、`kind: 'avoid'` 反向避坑。

<at-decision-card data-key="decisionCard3"></at-decision-card>

## 改动清单：本次改了什么、动了哪几块

版本说明与 PRD 的「本次改动」用 ChangeList——`kind` 区分新增（`add`）/ 变更（`change`）/ 移除（`remove`），`modules` 以徽标列出涉及的模块，扫一眼就能看出覆盖面。

<at-change-list data-key="changeList6"></at-change-list>

## 风险清单：影响与当前处置

「影响与风险」不要写成流水账：RiskList 强制每条都写清「影响」与「当前处置」，并用 `handled` 标明是否已在本方案内闭环——读者不会把「明确不修」误读成「已修」。

<at-risk-list data-key="riskList7"></at-risk-list>

## 自检清单：可勾选并记忆进度

每章末尾的「本章验收」用 Checklist——可勾选、进度条、按 `storage-key` 记忆在 localStorage（刷新不丢）。同课程多个清单请给不同 storage-key。

<at-checklist data-key="checklist4"></at-checklist>

## 下一步阅读卡

每章结尾的「下一步：…」建议用 NextUp——比纯文本好看，可多目标（推荐 / 可选 / 深入）。

<at-next-up data-key="nextUp5"></at-next-up>
