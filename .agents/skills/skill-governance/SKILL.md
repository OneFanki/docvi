# Skill 治理规范（本项目专属）

**适用范围**：仅约束本项目 `.agents/skills/` 下的项目级 skill。不约束系统级 / 官方插件 skill——`skill-creator` 教打法，本文件立规矩；冲突时以本文件与 `AGENTS.md` 为准。

## 前置判断：该不该沉淀成 skill？

先过**判断四问**：

1. 是**事实**还是**做法**？事实（架构、协议、现状）→ `docs/`；做法（步骤、API、禁止项）→ skill。
2. 会被**复用 ≥2 次**吗？一次性任务禁止写 skill。
3. 需要**自动触发**吗？不需要触发的参考资料放 docs。
4. **谁变谁改**？没有明确维护归属的不要沉淀。

**归属判断**：可执行步骤、最小示例、禁止项 → skill；架构决策、设计推导、实现态快照 → docs。

## skill 是路由入口，不是内容仓库

- 业务细则与实现态事实的真相源一律在 `docs/`；skill 只写「什么场景触发 + 先读哪份文档 + 最小结论」。
- 正文允许：可执行步骤骨架、结论级硬规则（不打开文档也不能违反的少数几条）、决策原因、指向真相源的链接。
- 同一用法只保留一个详细版本：skill 写用法入口并链接 docs 依据；docs 写设计并链接 skill 场景。

## 能力域归并（硬约束）

- **一个能力域只保留一个 skill**，不按 API / 函数 / 页面拆分。
- 新增前先判断是否属于已有能力域：是 → 并入，不新增；只有全新能力域才新建。
- 发现多个同域 skill → 合并，不留双份。

## description 约束

- **上限 80 字符**（按字符数）。
- 只写**触发场景词**，不写结论 / 避坑提示——结论留给命中后的正文。
- 写得 pushy：并列全场景词，覆盖「没明说但明显相关」的表述。

## 结构规范

- 路径 `.agents/skills/<name>/SKILL.md`，不用 `.zcode/skills`、不用插件机制承载项目知识。
- frontmatter 只两字段：`name`（小写 kebab-case，与目录名一致）+ `description`。
- 正文骨架：**结论（如适用）→ 步骤 / 注意点 → 变更触发**。
- 正文过长时拆到 `references/`，SKILL.md 只说「何时读哪个引用」。

## 维护规则（强制）

- 修改 skill 覆盖的代码或协议 → 同步更新 skill，不留过期内容。
- skill 与 `AGENTS.md` / ADR / 代码冲突 → 以硬约束与代码真相为准，并修正 skill。
- 文件移动或重命名后，修正所有 skill 内的路径引用。
- 新增 / 删除 / 改名 → 同步 `SKILLS-INDEX.md`，跑 `pnpm skills:check`。

## 校验清单

- [ ] description ≤ 80 字符，只写触发词？
- [ ] 属于已有能力域吗？若是，为什么没并入？
- [ ] 正文无架构快照，实现态事实已链接 docs？
- [ ] 写了「变更触发」节？
- [ ] 索引已同步？

## 变更触发

- 本文件、`AGENTS.md`「技能沉淀规范」、`SKILLS-INDEX.md` 任一处改动 → 三处口径核对一致。
